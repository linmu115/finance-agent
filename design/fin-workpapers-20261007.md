# 金融底稿家族 · N2 spec（2026-10-07）

方向：Claude；实现：Codex N2 会话，在独立 git worktree 分支 `feat/fin-workpapers` 上开发，完成后由主线合并。主线 spec 见 `design/harness-v2-mainline-20261007.md`，开发准则见 `AGENTS.md`，两者都必须遵守。

## 为什么做

目前金融组与通用基线做的是同一件事：自己写 Python 算数。金融组之所以能更强，应该是因为它能用一次调用，拿到分析师级、来源可追溯、语义正确的底稿；模型只负责判断、取舍和解释。底稿是金融组独有的能力，基线没有。

## 统一契约

- 一个宿主侧工具 `financial_workpaper(project_id, kind, …)`，只在金融配置下暴露，不调用 LLM，不依赖 Docker。kind 包括 `statement_analysis`、`comparison`、`report_audit`、`expectations`。不要为每个 kind 另起工具名。
- 输出统一采用现有 `service/analysis_report.py` 的 report 对象：tables、columns、rows，单元格是带类型的 cell，有 fact_id/record_id 或 `{value,unit,currency,source}`。宿主侧渲染为 CSV、Markdown 和必要的图，作为本次回答的附件交付，并登记进主线 A1 的“数值表”，这样回答可以写 `{{table:…}}`、`{{表.行键.列}}`。
- 每张底稿包含一张 `observations` 表：按幅度排序的确定性数值发现。只陈述数值关系，例如“毛利率下降 7.73 个百分点”“净利润为正而经营现金流为负”，不推断因果；因果由模型结合原文给出。
- 所有比率和变化都由未舍入的原始金额计算。百分比与百分点、合并与归母、应计与现金、披露与机构预测，固定在列定义里。
- 缺数据就留空，并写明缺什么。不估算，不挪用其他期间。未知不等于零（AGENTS.md）。
- 工具结果只返回紧凑摘要：表名、列与单位、行键、observations 前几条。完整数据在附件和数值表里。

## K1 statement_analysis（财报分析底稿，优先级最高）

- 输入：主体口径（默认合并，可选母公司）、期间（默认最新期与可比期）、可选关注点。
- 表：
  - `income`：收入、毛利、各项费用、营业利润、财务净收益、税前利润、所得税、净利润，合并与归母分列。
  - `ratios`：毛利率、费用率、净利率及其变化（个百分点）、增速。
  - `cash`：CFO、CFI、CFF；披露的直接法项目；`bridge` 每行带方向词“加/减”，由符号和分类决定，例如收到的利息在经营活动中为“加”；CFO/净利润转化率。
  - `working_capital`：应收、存货、应付及其变动；周转天数只在期初期末余额齐全时计算。
  - `observations`。
- 复用现有 `get_financial_metrics`、`calculate_financial_metrics`、`financial_quality` 的计算，不重写一套。
- 验收：
  - 对卡罗特 2025 中报（已入库，项目 `03b52dde-…`），与上一轮评审的独立参照逐项一致：收入、CFO、两条现金桥、毛利率变化 7.7321pp、归母与合并分列、财务净收益的位置；
  - 利息收款在桥中为“加”；
  - 对瑞和中报再做一次不同公司的检查。

## K2 comparison（同业与跨期比较底稿）

- 输入：多个主体，或同一主体的多个期间；按指标集比较。
- 表：
  - 共同比利润表和资产负债表关键项；
  - 杜邦 ROE 拆解（净利率 × 周转 × 权益乘数，平均余额口径）；
  - 现金转化；
  - 营运天数；
  - 增速；
  - `comparability`：财年截止日、报告口径（合并/母公司）、币种、会计准则、重述标记的差异，只列有据可查的；
  - `observations`。
- 验收：伊利 2023/2024 年报跨期、美的与海尔 2024 同业（如未入库，先完整入库，入库费用单列，AGENTS.md）。抽查不少于 30 个数值与原文一致；杜邦三因子乘积等于 ROE，残差列出。

## K3 report_audit（研报内部勾稽审计）

- 输入：一份已入库研报。
- 确定性核对：
  - EPS = 归母净利润 / 股本（各年）；
  - P/E = 价格 / EPS；
  - 增速与相邻年预测一致；
  - 毛利率与收入、成本一致；
  - 目标价与报告所述估值方法和参数复算一致（报告给出足够参数时）；
  - 同一指标在不同页的取值是否一致；
  - 年份、单位、币种标注是否前后一致。
- 每条结果给出：涉及的记录、原页码、复算值、差额、是否超出披露精度可解释的范围。参数不足就写“无法复算”，不猜。
- 这是按需调用的工具，不加进入库流程，不新增入库检查环节。
- 验收：CMBI 卡罗特研报应能复现已知问题：DCF 标题年份与预测期不符，目标价与 EPS 舍入精度差异。国信伊利研报再做一次。

## K4 expectations（预期差账本）

- 输入：主体和指标（收入、净利润、EPS 等）、可选截止日。
- 表：
  - `ledger`：机构 × 发布日期 × 预测年度 × 指标，取值来自研报记录。
  - `revisions`：同一机构对同一年度的预测修正轨迹。
  - `actual_vs_expected`：已披露实际值与各机构最近一次截止日前预测的差额和差异率，以及最大、最小偏差机构。
  - `observations`。
- 严格遵守“截至某日”：截止日之后发布的预测不进入当时的预期；日期不明的单列，不混入。
- 数据：同一公司需要多份研报。请挑一家已有年报的公司（建议伊利），补充 2–3 份不同机构或不同日期的公开研报并完整入库，入库费用单列。如获取受限，先用现有材料做出可运行版本，并说明还缺什么数据。
- 验收：用补充资料生成伊利 2024 年净利润、EPS 的预期差表；数值与研报原页一致；截止日过滤有单测覆盖。

## 实施与协作

- 在 worktree 中开发，并运行 Python 单测、类型检查和构建。读取真实数据时，用 `data/active` 的只读副本或临时复制的 SQLite，不写主库，不重启 3001。
- 注册工具时只改动必要的几处：工具注册、金融配置暴露、宿主侧交付挂钩。领域指导只加一两句“何时用哪个 kind”，主线会在 B4 统一瘦身。
- 顺序：
  1. 契约与 K1，完成后回报，主线可以先合并 K1；
  2. K3；
  3. K2；
  4. K4（含资料补充）。
- 每个 kind 完成后简短回报：实现要点、验收数据、与 spec 的偏差和理由。
- 保护主目录的未提交改动和历史数据。不启动其他服务端口。需要 Docker 的验证（如有）由主线统一安排。
