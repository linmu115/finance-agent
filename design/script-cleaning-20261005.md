# Python 脚本清洗与任务用量验收（2026-10-05）

本次按用户确认的方案改变金融清洗工具，不增加 Pi 循环次数上限或第二套上下文管理。Pi 继续规划、调用工具、压缩历史和重试；清洗保持最低 low，疑点可 high。

## 已实现的处理流程

1. 上传资料并解析 PDF 原文、表格和坐标，保留不可变来源。
2. `process_documents` 返回待处理表和持久检查点。
3. 模型读取表头和上下文，调用 `run_cleaning_script` 编写 Python 规则。复用已有规则可通过 `script_refs` 引用已校验的同项目脚本，无需反复输出代码。
4. 脚本在现有 Docker 沙箱内运行，读取原表并产生“原行列 → 指标、期间、单位、口径”的映射。数值不由模型逐条重写。主机重新从原始单元格计算数值，校验数值区间、单位和行覆盖。
5. `get_cleaning_result` 展示原文、映射、示例结果和异常；模型核对语义并提交逐表意见。程序校验失败的表不可入库；语义仍不确定的表保留“待核验”。
6. `commit_cleaning_result` 沿用已有事务和历史记录入库，记录脚本、原文、候选结果哈希与复核意见。完成的表写入持久检查点，继续剩余表。

程序另检查未识别主体仍被保存为文件名、同表不同明细使用相同指标/期间/维度等冲突。合并格包含多条逻辑行时，映射可显式指定 `row_subject=false`，避免将第一条指标误加为其他数字的维度。原始文档已入库后的局部修复另返回 `pending_script_tables`，不能把文档旧的完成状态当作本次修复完成，也不会因此提前切回高强度分析。

模型的代码只能在无网络、只读输入、无数据库/密钥挂载的沙箱内运行。通用 SQL/DDL、跨项目和破坏性操作的逐次授权机制保留。脚本复用验证项目归属和原始代码哈希。重试提交具有幂等性，目标表被其他操作更新时需要重新核对。
