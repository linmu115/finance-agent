# v3 P0.3–P0.5：N3 迭代与契约

基线 328b8e244deb2c75769846eb9093b4aa4d7d6750，分支 feat/harness-v3-ingestion。用户已授权开发、复制库零模型验收；不合并、不部署，不写生产事实。生产入库看护优先，记录在 f15-preparation-ledger-20261008.md。

## 已确认范围与基线

- P0.3：来源支持的描述性维度可以被底稿采用；分部、地区、产品、关联方、明细构成等切分保持隔离。海尔 t9 披露扣非必须真正被采用。
- P0.4：来源行名匹配标准词表时规范化指标，保留原 ID；未知项照常保留并返回待核清单。新提交与已有事实重新应用走同一规则，保留历史。
- P0.5：模型与用户读到资料可用性和完成/待处理/搁置计数，运行失败信息与资料状态分开，不能把部分可用资料显示成整体 failed。
- 复制库初始事实：伊利 2162 条、海尔 2196 条；包含伊利三季报，仅复制指定项目/文档，未读取 held-out。
- 海尔期间基线：12 条季度、3 条累计直接报候选冲突，另有依赖这些季度的未知累计。t12 标题位于 C/F/I/L 列，实际金额位于 B/E/H/K；底稿追加了空格候选。该原因不同于 financial_item 排除，需在期间原表适配处局部修复。t12 同一金额格另存在不同指标的重复映射，不能一律忽略 financial_item。

## 与 N2 的契约交集（实施约定）

- `standard_metrics.py` 继续作为规范 ID / 概念 / 原行标签的单一来源，既有 `WORKPAPER_ALIASES`、`standard_metric` 调用不变。增加精确原标签查询接口；规范化不得用宽泛子串命中、不得把增长率列变成金额。
- 新模块 `metric_normalization.py` 负责来源支持的指标规范化与原 ID/待核证据；提交和重新应用共同调用。
- 新模块 `dimension_semantics.py` 负责维度角色判定。`financial_workpapers.dimensions_ok(record)` 签名不变，委托该模块判断；保留维度原值和角色依据，不删除切分性维度。版本维度与 restatement 一致后由现有期间选择逻辑处理，不混合调整前后。
- N3 对 `financial_workpapers.py` 只改维度入口与必要的同版本候选选择；不改 N2 的主体、期间定位和流水线。对 `workpaper_periods.py` 只处理已有原格候选与季度原表适配重复导致的假冲突。
- P0.5 从已提交的表级结果计算文档公开状态；底层运行状态和错误原文仍保留。`list_documents`、`get_document`、目录和前端共用同一公开描述。

## 验收与不采用的方案

- 先保存五类底稿与事实基线，之后比较披露扣非采用、期间候选、核心未承接 ID、全部附带变化、值/币种/坐标/主体不变与重复应用零变化。
- 不用“只有一条记录”作为唯一语义依据；不能把未识别维度默认当描述性。不得为消除冲突任意选择非空值或不同数值。
- 不重新调用模型，不修改生产数据；待主线合并后再另行授权应用。

## 实现与交接契约

- `standard_metrics.VERSION=standard-rows-5`，新增 `exact_standard_metric(label)`，仅查规范化后的完整标签。将既有 fallback 中收入、归母、资产、负债、成本、毛利、EPS、ROE 标签显式移入同一词表，新增扣非完整中文表述；迁入标签与原 LOOKUP 无冲突。69 个底稿概念和既有别名不变。
- 事实的 `normalization.metric_aliases` 保存旧 ID；`metric_normalization` 保存原行/列坐标和规范化依据。既有 `canonical_rows` 在覆盖模型 ID 前也保存该别名，避免新提交路径比重新应用路径少历史信息。
- `normalization.dimension_roles` 只登记有来源依据的角色。`financial_item=descriptive` 必须同时满足原行标签、实际指标和维度值对应同一规范指标/概念，并且同指标、期间、主体、口径、版本只有一个数值；只有单条记录不足以成立。其他分部、产品、地区、关联方或明细维度继续阻止作为合计取数。
- `version` 只有与 `restatement` 一致才标为 `comparison_version`；底稿从同组比较版本中优先采用调整后数。没有删除原版本、原维度或原值。
- 无法匹配的 ID 照常提交。`get_normalization_details` 的普通和 `review_only` 返回中都有独立分页 `metric_review`；它是待核线索，不把全部明细指标误称为质量错误，也不阻断提交。
- `state` 表示文档可用性，`processing_state` 保留底层运行状态；`status_label` 与 `ingestion` 给出完成/待处理/搁置计数。沿用宿主选择最早未完成断点的规则，但完成数来自实际提交回执。已提交疑点仍可分析，未提交内容不能冒充已披露值。研报正文未读完时不会因表已完成而显示全完成。
