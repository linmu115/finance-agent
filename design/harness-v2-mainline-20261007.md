# 金融 harness 第二阶段 · 主线 spec（2026-10-07）

方向负责：Claude；实现与验收：Codex 主线程。并行会话：N1 评测台（`design/blind-eval-bench-20261007.md`），N2 金融底稿家族（`design/fin-workpapers-20261007.md`）。

## 0. 目标与可信度原则

目标：在同模型、同资料、同问题的条件下，金融 Agent 在金融正确性、专业深度、交付一致性上稳定优于通用 Pi，且成本不高于基线。

- **通用交付基建两组共享。** 本文 A 部分同样给基线。金融组的优势只能来自金融能力，也就是 B 部分和 N2 的底稿家族。这样赢了，才说明 harness 有专业价值。
- **不靠加提示词。** 每项能力都以“模型少做、程序多做”的形式出现。被程序接管的说明同步删除。
- **遵守 AGENTS.md。** 不新增 LLM 复核轮次。只有程序确定发现矛盾时，才回给模型一次精确的修复信息。不做防御性分支。
- 真实对照的设计和盲评由 N1 负责。主线只做确定性验证，以及 3001 上的少量冒烟测试。

## 1. 诊断依据（摘要）

- 四轮对照中，核心计算基本都对。实质错误发生在“程序结果 → 模型重抄、缩放、叙述”的接缝，类型包括转写、缩放、方向语义、表格错格和版式。
- 金融组与基线一样写自定义 Python，金融工具采用率低或中途放弃，所以金融组实际上没有用上金融能力。
- 更新题没有发生上下文压缩，9 个更新任务都看得见旧脚本和 run_id。但 `source_run_id + edits` 被描述成修复手段；金融模型更新又要求先存过模型。复用路径比重写更贵。
- `run_financial_model` 的 DCF 要求完整的经营预测和 ROIC 终值。真实题目是“研报给定 FCF + WACC/g”，这个工具表达不了，所以调用次数为 0。
- 详细证据见 `docs/evidence/seam-diagnosis-20261007.json`（诊断完成后以其为准，与本节冲突时更新本节）。

## 1b. 诊断后修订（依据 `docs/evidence/seam-diagnosis-20261007.md`）

诊断修正了三点判断：

1. **最大的接缝是“算出来的值没回到模型眼前”，而不只是“抄错”。** C1 的 33.65%/7.73pp、E2 的 11.23 只存在于产物文件中。run_analysis 只回传 stdout（脚本打印的往往是“report json created”），get_artifact 只给元数据。模型是在没看见结果的情况下写回答的。因此新增 A0，排在最前。
2. **统一报告不是没人用，而是失败率太高。** report 文件协议 36 次中失败 24 次；`{{}}` 17 次中失败 12 次；edits 30 次中失败 20 次。改进方向是让接口接受模型想表达的意思，而不是再加说明。因此新增 A1b，用历史失败载荷回放验收。
3. **利息方向错误在基线中同样出现，不是金融指导诱导的。** 这是模型的普遍概念错误，所以由 N2 K1 在桥接表里用程序给出方向词，属于真正的金融增益。

### A0 计算结果回传（最高优先级）

- run_analysis 结束时，把本次产生的全部数值表直接放进工具结果，包括 report、analysis_report.json 和 save_table 的表、/output 下可解析的 CSV、模型结果表。每张表给出：
  - 表名、行键；
  - 列名、单位、币种；
  - 精确值。
- 内容超出预算时按表截断，明确写出“已截断：剩余 N 行，用 get_artifact(…, rows=…) 读取”。不能静默截断（AGENTS.md）。
- get_artifact 对 CSV、JSON、MD 这类文本产物，按需返回内容；可指定行范围。
- 两组共享。这是通用能力：模型必须看见自己算出的东西。
- 验收：
  - 回放 C1、E2 的产物，确认工具结果中出现 33.65、7.73、11.23 及其所在行列键；
  - 统计全部历史 run 的回传字符数分布，给出预算建议，评估对输入 token 的影响。

### A1b 接口失败率治理（历史失败载荷回放）

- 从诊断 JSON 中取出 report 文件协议、report 参数、`{{}}` 占位符、edits 的全部失败调用及原始错误，按根因归类。
- 对每类做出选择：要么改成接受模型的本意（例如单位写法、行号与行键、列名大小写或空白、ratio 与 % 的自动处理），要么给出一次就能改对的错误信息（附候选值）。不加新说明文字，不加确认环节。
- 验收：把这批原始失败载荷重新提交给新接口（确定性回放，零 LLM），报告其中多少现在成功、成功后的结果是否正确、剩余失败是否都给出了可直接修正的信息。真正有歧义的输入（例如“百万”不带币种）仍应拒绝，并在回报中单列。

## A. 通用交付基建（两组共享）

### A1 回答数值绑定

- 本轮“数值表”收录以下来源，同名时后者取代前者：
  - run_analysis 产出的 report/analysis_report.json 表、save_table 表、模型结果表；
  - /output 下表头单位可解析的 CSV；
  - 宿主侧金融工具（run_financial_model、N2 底稿）交付的 report 对象。
- 最终聊天回答支持三种写法：
  - `{{表.行.列}}`：单值，带列单位，按该列小数位显示；
  - `{{table:表名}}`：整表，渲染为 Markdown 表格；
  - `{{chart:文件名}}`：图片。
- 宿主在回答落盘前解析，使用与 report.md 相同的格式化函数。行号允许用行键（例如 `forecast.2025E.revenue`），减少数错行。
- 解析失败时，把失败原因作为后续消息回给模型，附可用表名、列名和行键，模型修正后再结束。正常情况下不出现。
- run_analysis 和金融工具的结果里列出紧凑的可引用清单：表名、列及单位、行键，不倾倒数值。
- 验收：
  - 单测覆盖三种占位符、行键、单位换算显示、同名取代、解析失败回路；
  - 用 E2、C2 的原始数值表回放，整表嵌入后不可能再出现 12.07 错格和 10 倍缩放。

### A2 参数重跑：任何脚本都是可复用模型

- run_analysis 成功后，宿主用 AST 静态解析脚本顶层的字面量赋值（数字、数字列表、只含数字的 dict），在结果中列为“可覆盖参数：WACC=0.122，G=0.01，FCF=[…5 项]”。
- `run_analysis(source_run_id, params={NAME: 值 | {"+": d} | {"*": k}}, params_order=[...])`：
  - 按覆盖值重跑原脚本，算子逐元素作用于列表；
  - 未知参数名直接报错，并列出可用参数。
- 新旧两次运行的同名数值表自动生成 old/new/delta 表，交付并登记到 A1。
- 给出 params_order 时，宿主按前缀依次重跑（base → +p1 → +p1+p2 …），对所有同名数值单元给出逐项贡献，并说明贡献依赖替换顺序。
- run_analysis 的说明改为“改假设时用 params 重跑，不需要重写”；edits 保留给真正的代码修改。
- 验收：
  - 用冻结的 D2、E2、F2、C2 原脚本，`params={"WACC":{"+":0.005},"FCF":{"*":0.9}}`（参数名以实际脚本为准）重跑，结果与 D3、E3、F3、C3 的冻结参照逐格一致；
  - 逐项贡献与参照一致。

### A3 图表在 matplotlib 层修复

- 在 plot_runtime.setup() 中默认开启 constrained layout，两组共享。
- 给 Figure.savefig 加钩子：
  - 文字落在 AxesImage、QuadMesh 或柱体上且对比度低于 WCAG 3:1 时，按底色亮度自动改为深色或浅色；
  - 用 renderer 检测文字之间、色条与子图之间、标题与子图标题之间的重叠。先切换布局引擎自动修复；仍重叠的，在 run 结果中逐项报告：文件、元素 A、元素 B、重叠面积。
- 不改模型给出的数据、刻度和配色方案。
- 验收：用上一轮和本轮冻结脚本重新渲染全部有缺陷的图（F3、C3、E3、D3 的色条和标题；C1 负值标签；各热图的深色格），统计修复数和剩余报告数。

### A4 同名产物版本

- 同一回答内的同名文件只挂最新版本为附件；正文链接按文件名解析到最新版。旧版本保留在运行记录里。
- 验收：用 G1 回放，`chart_1.png` 能唯一定位。

### A5 交付一致性扫描（零 LLM）

- 扫描对象：回答正文、本轮 .md 附件和 CSV 表头中的“数值+单位”。对照 A1 数值表和本轮查询到的来源记录，分类为：精确、舍入一致、数量级不符（×10^k）、表格错格、无对应。
- Markdown 表格按表头和行键对齐到数值表，逐格比对。
- 第一阶段只在观察模式下回放全部旧会话，给出对已知缺陷的查全率，以及对已判正确回答的误报。至少要覆盖：C2 ×10、D2 CSV RMB bn、E2 错格、C1 7.74、F2 EPS 0.63→0.83、F2 的 6.8/1.3。
- 误报为零，或每条都可解释时，才启用“数量级不符”和“表格错格”两类：回给模型一次。仍不一致的，在回答下方向用户可见地标注。是否启用由我根据回放数据决定。

## B. 金融专业层（仅金融组；底稿家族见 N2）

### B2 估值：FCF 序列 DCF 快速路径与专业诊断

- run_financial_model 新增 kind `dcf_fcf`，最小输入如下：
  - 预测 FCF 序列：每项可以是 `{record_id}`，也可以是值；
  - 估值基准时点和折现约定；
  - WACC、g，以及可选的净现金/净债务、少数股东、股本和汇率，同样可用 record 引用。
  - 不要求经营预测和 ROIC。
- 默认产出：
  - EV、股权价值、每股价值；
  - WACC×g 敏感性网格，默认 ±1pp、步长 0.5pp，可覆盖；
  - 终值占 EV 比例；
  - 隐含退出倍数：有 EBITDA 或净利润记录时给 EV/EBITDA 和 P/E；
  - 有研报目标价记录时，给出与目标价的差异桥：WACC、g、FCF 路径、汇率、股本逐项贡献，并说明顺序依赖。
- 更新：`source_model + overrides`，overrides 支持与 A2 相同的 `{"+":d}`、`{"*":k}` 算子，自动返回 changes 和逐项贡献。
- 全部结果以 report 对象交付并登记到 A1；每个数值单元保留 record 来源。
- 验收：用 CMBI 卡罗特研报的冻结参照（EV 5329.22…、每股 10.891…、9 格敏感性、更新后 9.41 等）逐格一致；EPS 等来源值直接由 record 带入。

### B3 金融语义固化

百分比与百分点、合并与归母、应计与现金、披露与机构预测，都在底稿和模型的列定义中固定，回答引用时自带正确单位和口径标签。B2 的列定义由主线完成，N2 的由 N2 完成，共用同一套列类型。

### B4 金融指导与工具说明瘦身

- FINANCE_TASK_GUIDANCE、RESEARCH_PROMPT 中的建模段落、run_analysis 和 run_financial_model 的说明里，被 A、B 和 N2 接管的机械规则一律删除。保留“遇到什么问题用哪份底稿或工具、如何解释”的领域判断。
- 写清遇到以下题型时的默认路径：
  - 财报分析：先调用底稿；
  - 估值：用 dcf_fcf，或其他已有 kind；
  - 更新：使用 overrides 或 params。
- 交付时列出瘦身前后两组系统提示和工具说明的字符数。目标是金融组总说明减少 30% 以上。
- 在 A 部分和 N2 合并后再做。

## C. 主线验证边界
