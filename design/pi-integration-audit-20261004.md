## 已定位并在源码修正

| 宿主行为 | 后果 | 源码状态 |
| --- | --- | --- |
| 默认 64 次工具调用上限，设置只允许 1–100 | 真实伊利任务完成 64 次调用后，第 65 次 `save_research_report` 被拦截并触发整个任务 abort | 已删除执行检查、后端字段与前端输入；旧设置字段会被解析器移除 |
| 最近 8 次工具结果以外、超过 8192 字符的可重读内容直接换成回执 | 尚未接近窗口上限也会丢失仍需使用的数据，计算调用也会推动其过期 | 已删除按年龄/次数裁剪；历史读取正文不再因此过期 |
| 超过 24000 字符的旧版完整目录直接换成回执 | 另一条独立于上下文压力的内容删除路径 | 已删除；现有分页接口继续可用 |
| Pi 原生网络重试被覆盖为最多 1 次 | 连续两次短暂上游故障就无法恢复 | 已删除覆盖，使用安装版本 Pi 默认重试策略 |
| 同一轮处理资料失败后，相同参数永久禁止再试 | 已保存检查点存在，当前任务仍无法尝试恢复 | 已删除失败锁；取消、无效凭据、余额与明确预算终止仍生效 |
| 原网页读取缓存保存失败的 Promise | 后续同 URL 请求直接重复之前的拒绝，无法真正重试 | 失败条目退出缓存，成功快照继续复用 |
| `getLastAssistantText()` 非空便可能标为完成 | 上游最后输出因 length 截断也可能被标为成功 | 在 Pi 原生恢复结束后仍检查最终 stopReason；残缺文字不标完成 |

## 仍存在的额外 Pi 接入行为

| 行为 | 实际作用与边界 | 分类与后续方向 |
| --- | --- | --- |
| 包装 `runtime.streamSimple` | 每次请求插入路由强度、输出预算、温度、JSON 格式、用量记录和历史投影 | 包装承担必要记账，但覆盖面过大；应缩减到必要适配，不替代 Pi 的循环 |
| 所有请求固定 `temperature:0` | 全局覆盖上游采样默认；是否被模型实际采用由提供商决定 | 非安全约束，尚未删除 |
| 自定义 `session_before_compact` | 拦截压缩回调，再调用 Pi 原生 `compact()`；追加金融摘要要求、来源索引、审计；失败时写程序恢复记录 | 已使用 Pi 选段与恢复主流程，但不是完全原生默认摘要流程；应继续收敛回调职责 |
| 压缩 80% 触发、近期约 16% 保留 | 自动模式参考 DSH，并预留输出和请求余量；当前 1048576 窗口触发值为 838860，不是设置文件兼容字段中的 96000 | 统一模型窗口参数，不分清洗/分析；可保留为 Pi 配置，不再增加第二套裁剪机制 |
| 摘要输出上限与重试覆盖 | 默认摘要最多 8192；自定义摘要请求使用 off，重试最多 1 次、初始延迟 250 ms | 仍是额外覆盖，尚未调整；不能声称整个重试层已全部回归 Pi 默认 |
| 程序摘要失败回退 | 使用实际用户指令、检查点、来源引用继续；原会话保留 | 用户曾明确要求检查点与失败恢复；业务状态保留，但应避免把它扩展成另一套上下文调度 |
| 工具结果视图投影 | 目录去重复审计，财务查询去重复规范化历史；保存成果返回结果与版本引用，正文保留在配对调用和成果中 | 业务工具的返回结构，不是按任务类型切换记忆策略；精确数值、期间、口径和来源不得丢失 |
| 运行中不接受新用户消息 | `RunManager.start()` 对活跃会话返回 409，未接入 Pi steering/follow-up | 非安全限制，属于尚未完成的交互接入；源码尚未修改 |
| 服务重启只标失败 | 恢复时保留 Pi 日志和入库批次，但应用要求用户在原会话重新发消息 | 非 Pi 能力限制，属于宿主恢复流程欠缺；自动重放结果未知的写操作必须先核对 |
| 模型仅由应用设置注册 | 不使用全局 models.json，不自动刷新 Pi 模型网络目录；固定走 OpenAI-compatible adapter，关闭 developer-role/store 等兼容字段 | 配置与适配边界；不等于禁用应用联网工具。上下文与输出能力目前依赖配置填写 |
| 仅特定 DeepSeek 官方地址开启现有推理格式分支 | 路由强度适配通过 hostname 判断，兼容网关未必进入同一分支 | 提供商适配局限，非权限保护；尚未修改 |
| 禁用默认提示模板和主题加载 | 使用应用自己的系统提示、界面与样式 | 应用集成选择，不是长循环需要的约束，不应包装为安全要求 |

## 用户确认的业务能力与明确预算

| 项目 | 当前规则 | 与 Pi 的关系 |
| --- | --- | --- |
| 思考路由 | 清洗最低 low；具体异常可 high；分析/建模 high；路由由同一模型承担 | 用户明确确认的业务路由，保留；不应据此分裂上下文引擎 |
| 模型输出上限 | 主调用取用户设置，当前 32768；结构化抽取固定不超过 32768；路由固定 4096；JSON 仅用于抽取、路由和指定输出契约。配置校验允许上下文 4096–2000000、单次输出 128–131072 | 有些是必要请求参数，有些是宿主固定值；不得把单次输出限制变成任务总长度限制 |
| 入库检查点 | 每批结果与待复核状态保存于数据库 | 业务事务与断点续处理，保留；不控制主 Agent 的记忆释放 |
| 财务规则 | Decimal 计算、口径与期间说明、实际来源和数值核验、结构化报告/模型校验 | 金融专业性，应继续增强 |
| 费用预算 | 用户设置金额及报价后启用；当前正式实例未设置金额预算 | 明确资源预算，与隐藏工具次数上限不同 |
| 评测预算 | 仅传入 evaluation 时生效，约束模型请求数、token 和运行时间 | 用于明确的基准预算，不应应用于普通会话 |
| 每次附件 8 份、指标复核 12 个 | 宿主工具/API 参数限制 | 业务批量限制，非 Pi 原生或安全边界；大任务应支持分批完成 |

## 安全和权限边界

- 不开放 Pi 的宿主机内置 shell、任意文件读写工具；计算经隔离容器执行。开放这些工具会绕过数据库授权、项目范围或暴露宿主机资料。
- 工具名称白名单、参数模式和当前项目绑定；普通工具不能自行指定别的项目。跨项目读取通过逐次授权入口。
- SQL、DDL、删除、数值修改与分析代码提交数据库变更，仍逐次展示具体操作并等待用户批准；同一被拒操作本轮不反复申请。
- 不自动加载全局/无关目录中的可执行扩展、规则和技能；应用与当前项目的已启用技能和 agent.md 已通过显式 overrides 加载，不能误称全部关闭。
- 秘钥留在本机受保护配置；抽取桥接凭据只绑定当前任务；取消不会串到其他任务。
- 容器资源、断网/挂载隔离，单次代码执行 10–120 秒；MCP 单次请求 180 秒并支持进度重置；联网请求独立超时。这些不是整个任务总时限。传输超时属于资源可靠性措施，不全部等同于权限限制。
- API 401/402、明确预算耗尽、用户取消和无法保存审计记录仍会终止相关执行；不能为追求不停机而隐瞒这些真实阻塞。

## 验证记录

- 长循环：同一 Pi 任务 137 次工具调用（读取原表 1、计算 135、保存报告 1），成功保存并从成果存储读回正文。
- 压力场景：同样 137 次调用，在任务中途触发 Pi 原生压缩，继续到报告成功保存；没有孤立工具结果。
- 未达压力：经过 135 次计算，旧原表精确文字仍在模型输入中，摘要调用为 0。
- 同参数处理失败后在当前任务内重试成功；连续两次上游 503 后由 Pi 默认重试恢复。
- 未恢复的截断文字被标为未完成；旧保存配置/旧客户端带入的 maxToolCalls 不再恢复限制。
- 以上为隔离临时数据目录、真实 Pi 与真实财务服务、受控模型响应测试，不是新的 DeepSeek 实报或成本验收。
- 类型检查通过，完整 Node 回归 160/160 通过，`git diff --check` 通过。首次回归发现两项旧测试仍要求“释放原文/禁止第二次处理”；更新为新行为后重跑全套通过。日志见 `data/retests/harness-review-20261004/all-node-tests.log`。
