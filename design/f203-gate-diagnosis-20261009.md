## F2.1 修复项（都在已确认的 v3 P0/P2 范围内）

### F2.1-A　Markers 判定纠偏（金融层，负责人：N2）

1. **不再做否定式断言。** 证据不足时，状态改为 `unclassified`，说明写“未自动判定是否本期发生，需对照原文核对”。不再出现“不证明本期发生”这类结论性措辞。
2. **“已发生”升级适用于所有 kind**，不只限于 restatement。只要句中有报告期内或本期“完成 / 已 / 纳入 / 并表 / 收购完成”等明确完成语，就标为已发生，并保留原句。
3. **区分政策变化和估计变化**：句中出现“会计政策变更 / 执行……准则 / 解释第 N 号 / 重分类”时，标为政策变化；只有出现“会计估计变更”时，才标为估计变化。
4. **测试**：
   - 正例：用 Carote 年报 p12（并表完成）、p94（质保政策重分类）、p163（追溯调整）的原句；
   - 反例：模板段落、“不适用”勾选、泛泛的政策描述，必须保持 `unclassified` 或 `not_applicable`。
5. 判定只按通用语言规则，**不针对具体公司或题目写特例**。

### F2.1-B　瀑布图连续性检查（共享交付基建，负责人：main）

1. 在 plot_runtime 的诊断里加几何检查。对瀑布型柱图做链式校验，判定条件是：至少 3 根柱子，有非零 bottom，且正负值混合。
   - 起点的运行值是 0，或起始合计柱的顶端；
   - 每根变动柱的两个端点里，必须有一个等于上一步的运行值，另一个端点就是新的运行值。
   
   两种常见画法都能通过这个检查：负高度从 base 向下画，或者用绝对高度配合 `min(before, after)` 作 bottom。
2. 校验失败时，在 `plot_diagnostics` 里返回警告，指出具体是哪根柱子不连续；在金融组的警告中附上 `finance_charts.waterfall` 的用法。图片不自动改写。
3. 原版 Pi 组不启用这项检查（保持基线）。
4. 测试：
   - 本批 F2_X3 和 G2_X3 的脚本必须被标出；
   - `finance_charts.waterfall` 的输出、正确的手写负高度画法都不能误报；
   - 普通柱图和分组柱图不触发检查。

### F2.1-C　方向 lint 覆盖面（共享交付基建，负责人：main）

1. 交付检查的范围从 `.md/.csv` 扩大到 `.xlsx` 的字符串单元格，定位到 sheet 和单元格。
2. **期间顺序**：“由 X（降 / 减 / 下降 / 降低）至 Y”要求 X > Y；“由 X（增 / 升 / 增长 / 上升 / 提高）至 Y”要求 X < Y。英文的 `from X to Y` 加 `decrease/increase` 同理。
3. **关系断言**：出现“方向相反 / 反向 / 方向不同 / opposite / 同向 / 同方向 / same direction”时：
   - 如果在同一句话或同一表行里能解析出两个带符号的变化值，就直接判断对错；
   - 解析不出来时，给一条“关系方向断言需核对”的提示，并附原文和位置。这条提示不算错误，也不阻断交付。
4. 测试：
   - 本批 G1_X3、G1_X7、F1_X7 的文本都要被标出，F1_X7 那条以提示形式出现即可；
   - 用历史批次中正确的交付文本做误报回归，误报率写进验收。
5. F1_X3 这类“减少了差额”的语义错误，本轮不做规则覆盖，以免规则膨胀。
