## 实现边界

- 主分析和建模仍为 high，同一 DeepSeek 模型做任务路由。普通抽取最低 low；Python 与 Node 私有桥都将旧 `none` / `off` 请求提升到 low。实际 DeepSeek 请求必须带 `thinking.type=enabled` 和 `reasoning_effort=low|high`，并以实际 SDK 发送的请求做回归验证。试验工具只允许 low、compact-low、targeted-low。
- 表级 `column_defaults_json` 提供共同单位等字段；每个数据列仍必须显式列出。行级 `column_overrides_json` 的 `all` / `columns` 明确表达差异。程序展开成既有完整列映射后再物化和保存；旧 `columns_json` 保持完整替换语义，旧漏列继续报错。
- 第一轮实测发现：仅关闭思考会在复杂矩阵上降低期间判断质量，并且原 low 和 off 都存在误跳过股本/子公司财务表的问题。后续候选因此补充了通用质量保护，不是仅切换一个参数：为续表取回有物理页码的前序同列数表头候选、最近原文标题及单位行（最多 2,400 字符），由模型自行判断适用性；不由程序猜口径、期间或数值。页背景仍只发送一次。
- 模型判定整张数字表为 nonfinancial 时，必须再用 high 独立复核。已确认无财务含义才可保留跳过；旧未复核的排除结果在下一次处理时重查。原有有效财务批次不因此作废。校准得到的提示强调财务主体名称是维度、期初/变动/期末不能共用一个时点。实验是伊利同源校准，不是未见公司上的泛化验收。
- 线上的源文件、批次坐标和完整映射存储格式兼容，既有有效检查点继续可复用。新提示、思考策略与修复协议进入请求缓存指纹，审计保留实际提示和用量。
- high 修复只发送问题行和必要上下文，列问题用 `cell_patch`。程序限定可改行列；修复不得增加新问题、删除或改变原本有效的事实。缺少表级结构时才退回单片完整复核，仍检查已有事实不退步。
- 修复成本、失败请求计入对比。没有返回用量的失败不能视为零费用。输入缓存命中另计，思考 token 已包含在输出 token 中，不能重复相加。
