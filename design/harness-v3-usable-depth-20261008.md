## 进度门槛（内部止损点）

第一步只做 P0、P1.0 和 P2，合并后在开发集上做一次小规模三组对比（约 12–18 回合）。标准如下：
- 金融组实质缺陷明显少于 prepared；
- 解释与异常两项不低于 prepared；
- 已知输入不高于 prepared；
- 产品原因导致的整轮失败为 0。

达标后再继续 P1 其余部分和 P3，并在新 held-out 上正式评测。不达标就先回报、重新诊断，不继续堆功能。

方向：Claude。开发准则以 `AGENTS.md` 为准，优先于本 spec。评测期间（F1.x 冻结窗口）只允许在分支上开发，不合并、不部署。

## 为什么做

F1 系列的正式盲评结论是：金融组**没有证明优于通用基线**。

- **阶段 A（卡罗特，开发集，F1）**：实质缺陷通用组 3/6、金融组 1/6；金融组已知输入少约 28%。但深度没有更高：财报分析题的“解释”金融组 4 次评分都是 2 分，通用组为 3/2/1；“异常”两组都是 2 分。
- **H1/H2（held-out，F1.2）**：实质缺陷通用组 0/4、金融组 1/4，为方向措辞错误；深度两组持平；金融组已知输入多约 86%。
- **脱敏诊断**（`data/evaluation/blind-eval-heldout-diagnostics-redacted-20261008/`）：
  - held-out 上金融组 8 次底稿调用**全部**返回 `insufficient_evidence`，机制是主体定位歧义 5 次、收入期间定位失败 3 次。金融层在新材料上等于没有起作用。
  - 多出来的成本主要来自三处：目录和原表结果在多轮中被重复携带；金融组的系统提示和工具说明更长；失败后转为自由读取。
- **阶段 A 评审对深度的批评**：
  - 解释偏算术，没有用上原文给出的管理层原因，例如关税对毛利率、定期存款对利息、营运资金对现金转化的影响；
  - 管理层有定性说明、只是缺少定量桥时，被写成了“未知”；
  - 异常信号没有讨论替代解释和持续性，两个样本就写成了“连续”。
  - 金融组两次财报题**都没有调用** `variance_attribution`，而它自带“驱动因素原文对齐”。
- **伊利冻结前验收**（F1.3、F1.4）：入库指标名和底稿查找名分叉，造成 18 条假缺失；非经常损益表口径未定；海尔 t9 的扣非带 `financial_item` 维度，没有被采用。

结论：金融组要领先，首先要让**底稿在真实入库数据上稳定产出**，其次才是深度。

## P0　底稿在真实数据上稳定取数

1. **歧义要可行动，不能走进死胡同。**
   - 主体、期间、口径无法唯一确定时，返回候选，并附一行可以直接重调的参数示例，例如：
     - 候选主体：名称、文档、各自事实数；
     - 收入可用的期间列表；
     - 可用的口径。
   - 证据足以决定时由程序选定，例如文档档案中的报告主体、合并口径优先，并在结果中说明选择依据。
   - 不再返回不带候选的 `insufficient_evidence`。
2. **原表直读兜底。**
   - 核心报表行（收入、成本、费用、各级利润、经营现金流、主要资产负债项）缺少结构化事实时，如果标准报表原表存在（已入库或部分入库均可），由程序按 `standard_metrics` 确定性映射直接读原表计算。
   - 结果标注“来源：原表直读”，并附页码和表坐标。
   - 不估算，不补零。
3. **维度语义。**
   - 区分描述性维度（如 `financial_item` 与行名一致、同一指标期间只有一条记录）和切分性维度（分部、产品、地区、多值且可加总）。
   - 描述性维度不排除记录。
   - 用海尔 t9 和构造样例覆盖。
4. **入库指标规范化。**
   - 提交时，如果模型自造的指标 ID 的原行名与 `standard_metrics` 的标签匹配，就规范化为标准 ID，原 ID 保留为别名记录。
   - 匹配不上的照常提交，并列入待核清单。
   - 目标：明显降低“未承接指标”清单中核心类的数量（伊利 353 个、海尔 296 个，其中多数是明细项，不全是缺口）。
5. **部分入库的文档状态。**
   - 用“核心表已完成 / N 张待处理 / M 张搁置”取代 `failed`，让分析会话知道“资料可用但不完整”。
   - 这一问题曾导致 F1.1 中分析请求触发入库。
6. **验收（只用开发材料，不得使用青岛啤酒）。**
   - 伊利、海尔、卡罗特、茅台（samples）、瑞和上，五类底稿全部产出。每个 missing 项要么有原表兜底，要么有具体原因。
   - 用开发数据**构造**两种机制样例并覆盖单测：
     - 同一项目中有多个相近主体，例如 A+H 双披露或母公司与集团；
     - 收入期间标签非标准，例如年度标为日期区间、或比较列重述。

## P1　分析深度

0. **必经底稿流程（从“可选工具”改为“程序先跑、模型拿成品”）。**
   - 历次的教训：模型不主动调用金融工具。估值工具 0 次调用；阶段 A 财报题两次都没调用 `variance_attribution`；held-out 上的调用全部失败。
   - 新做法：金融配置下，宿主识别出财报分析类请求（公司或文档明确，问题涉及业绩、现金、质量、口径、异常、季度、预期等），就在模型开始推理前由程序跑完底稿流水线，产出一份**紧凑的分析底稿**，作为本次请求的上下文交给模型。底稿包含：
     - 关键数（已登记为 A1 数值表，可直接绑定）；
     - 利润与现金桥；
     - 主要变动归因及对应的管理层原文（附页码）；
     - 已触发的信号及追问字段；
     - 口径或期间未齐标记；
     - 缺失项及原因。
   - 模型仍可调用全部工具做补充。底稿流水线失败时如实写明原因，不阻断回答。
   - 底稿要控制体积：只放结论性的表和关键行，完整表以句柄方式按需读取。验收时成本不得高于 prepared。
   - 通用组和原版 Pi 不提供这份底稿：这正是金融层的增量。
1. **一次调用拿到分析包（解决不调用的问题）。** 财报分析类请求在一次调用中返回以下内容的紧凑结果：
   - 利润与现金桥；
   - 变动归因；
   - 异常信号；
   - 原文证据。

   工具说明要让这个入口成为显而易见的第一步。验收时统计采用率。
2. **管理层解释对齐。**
   - 对每个主要变动项（收入、毛利率、各项费用、财务收益、减值、经营现金流、营运资金项）和每个已触发的信号，程序在管理层讨论等章节检索候选原句，附页码，交给模型。
   - 原文没有说明的，明确写“原文未说明”。
3. **三层解释指导。**
   - 三层依次是：披露事实（管理层原话 + 页码）→ 量化影响（能算的算出来，算不了的写明缺什么）→ 推论（标注为推论）。
   - 把“未知”拆成“定性已披露、定量未披露”和“原文未说明”两种。
4. **信号追问。** 每个已触发的信号都要写：
   - 管理层解释；
   - 替代解释（季节性、备货、回款节奏、一次性因素）；
   - 持续性（如实写明样本期数，不足三期不写“连续”）；
   - 后续跟踪指标。
5. **尊重“口径未齐”标记。** 阶段 B 的 X5 四个回合全部出现口径错误：把归属不明的利润直接定为归母，也没有解决收入比较范围。`expectations` 等底稿标出的口径未齐、维度未齐，要进入答案的约束：
   - 标为未齐的比较，回答中不得写成同口径的误差或结论；
   - 交付检查发现这类写法时，走一次修复。
6. **验收。**
   - 在开发题（卡罗特 D1，伊利 X 题）上，用 F1.4 做对照，进行双遍盲评。
   - 金融组“解释”和“异常”的平均分各提高至少 0.5，实质缺陷不增加，已知输入不高于通用组。

## P2　方向措辞一致（交付基建，两组共享）

1. 分析沙箱提供 `fmt_change(delta, unit, pct=None)` 一类的格式化函数，统一输出“增加 X / 减少 X / 持平”。指导中要求涉及方向的文字使用它。
2. **交付前检查**：
   - 扫描最终回答和交付的 md、csv 文本中，方向词与带符号数值矛盾的组合，例如“增加 -”“减少 -”“下降 −x%”“同比增长 -x%”；
   - 发现后走一次 A1 修复回路，与占位符修复同一机制；
   - 修复后仍矛盾的，在交付中显示出来。
3. 单测覆盖中文、英文、百分点、括号负数等写法。
4. **答案绑定不能因一个占位符而让整轮作废。** 阶段 B 的 F1_X3：模型写了 `{{get_artifact(<id>, cashflow_reconciliation.csv)}}`，修复一次后仍写成 `{{get_artifact(...)}}`，整轮判为失败。阶段 A 的 F2_D1 也是绑定环节失败。处理方式：
   - **扩展宽容解析（A1b）**：形如工具调用、但其中的文件名或表名能唯一对应本会话某张表或某张图的占位符，按该表或该图解析，并记录这次改写。
   - **修复后仍无法解析时降级交付**：答案照常交付，无效占位符替换为醒目的“[引用无效：原文]”标记，在交付中列出，并计入一致性问题，不再让整轮失败。
   - **查清模型为什么把工具调用语法写进占位符**：检查 A1 指导和工具说明里是否有诱导性写法。金融组的两次绑定失败都出现在产物较多的回合。
5. **估值小节校验的误判与硬失败**（`server/answer-semantics.ts` 中的 `valuationSections`）。X7 两组各有 1 回合因此整轮失败。原因有三：
   - 关键词判定不处理否定，“本文不做估值或投资建议”也会触发；
   - 小节识别只认行首的标题或加粗，不认 `- **假设**：…` 这类列表项写法、表格写法和合并标题；
   - 修复一次后仍不满足，就判整轮失败。

   改法：
   - 估值判定只认真正给出估值结论、目标价、投资建议的句子，排除否定和引述；
   - 小节识别覆盖列表、加粗、表格和合并标题，判断小节是否有内容时按语义而不是按格式；
   - 提醒一次后仍缺失的，照常交付答案，在交付中显示“估值说明缺少：假设／风险／适用范围”，计入一致性问题，不再让整轮失败；
   - 用 X7 的两份失败答复构造回归单测（开发集材料，可直接使用）。

## P3　上下文瘦身

1. 已被消费过的大块工具结果（目录、原表、分析状态），在后续轮次替换为摘要，并附重新读取的句柄。要求：
   - 用 Pi 原生的上下文变换实现；
   - 不得删除仍被引用的证据；
   - 先实测，再改。
2. 精简金融组的系统提示和工具说明，目标是与通用组的差距显著缩小。
3. **验收**：同题条件下，金融组已知输入不高于通用组，质量不下降。
