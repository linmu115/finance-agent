# 信用分析工作流 v1（2026-10-13）

状态：草案，等用户确认后派给 Codex。比赛初赛版本（10/18）不受影响，所有开发在新分支上进行。

## 1. 为什么做

用户确认把**固收信用研究员**作为首要目标用户，买方股票研究员作为第二类用户，基金经理是报告的读者。

信用研究员读财报的重点和股票研究不同，关心的是：

- 有多少有息债务，什么时候到期，手上的现金够不够还；
- 有多少资产被抵押或冻结（受限资产）；
- 对外担保有多少，有没有被关联方占用资金；
- 经营现金流和 EBITDA 能不能覆盖利息。

这些数大多在**附注和“重要事项”**里，数据商结构化得不够细，而且要经得起内部评审，每个数都要能点回原文。这正好是我们“带页码入库、底稿先算、交付前逐句检查”的强项。

决赛的叙事也围绕这个展开：现场演示两个案例，一个是现成的伊利股票分析，另一个是新增的发债主体信用分析。

## 2. v1 范围

### 2.1 产出

新增一种底稿 `credit_analysis`，以及一个“信用分析报告”导出模板。底稿里的每一格都带来源页码和计算公式；缺的项目写明查过哪些范围、为什么缺，不编数。

**不输出信用评级或评级符号。** 信用评级在国内是持牌业务。产品只给出“风险关注点”，结论标注为推论，需要分析师判断。这一条要写进提示指令，并由交付检查拦截“评级为 AA”之类的表述。

### 2.2 底稿内容

期间默认取最近一期年末和上一期年末，同时给出变化。口径默认为合并报表。

**① 有息债务构成**

| 组成 | 窄口径 | 宽口径 | 来源 |
|---|---|---|---|
| 短期借款 | 计入 | 计入 | 资产负债表 |
| 一年内到期的非流动负债中的借款、应付债券、租赁负债 | 计入 | 计入 | 附注明细表 |
| 长期借款、应付债券、租赁负债 | 计入 | 计入 | 资产负债表 |
| 应付票据 | 不计 | 计入 | 资产负债表 |
| 其他流动负债中的短期融资券、超短期融资券 | 不计 | 计入 | 附注 |
| 长期应付款中的有息部分 | 不计 | 计入 | 附注 |
| 永续债（列在其他权益工具） | 不计 | 单独列示，不并入合计 | 附注 |

规则：

- “一年内到期的非流动负债”**只按附注明细拆出其中的有息部分**。拆不出来时，下限按 0、上限按全额，给出一个区间，并标注“一年内到期部分未拆分”。现有 `workpaper_signals.py` 的存贷双高信号只取下限，不把这部分计为有息；这里在它的基础上再补一个上限。
- 窄口径和宽口径都输出，让分析师自己选，回答里写明用的是哪个。

**② 期限结构**

- 短期有息债务 = 短期借款 + 一年内到期的有息部分；宽口径再加上应付票据和短融。
- 短期有息债务占全部有息债务的比例。
- 附注里有借款或债券的到期分布表时，按“1 年内、1 到 2 年、2 到 5 年、5 年以上”列示；没有就只分一年内和一年以上。

**③ 偿债能力**

| 指标 | 公式 |
|---|---|
| 现金短债比 | （货币资金 − 受限货币资金）÷ 短期有息债务 |
| 资产负债率 | 负债合计 ÷ 资产合计 |
| 有息债务资本化比率 | 有息债务 ÷（有息债务 + 所有者权益） |
| EBITDA | 利润总额 + 费用化利息支出 + 固定资产折旧 + 使用权资产折旧 + 无形资产摊销 + 长期待摊费用摊销 |
| EBITDA 利息保障倍数 | EBITDA ÷（费用化利息 + 资本化利息） |
| 有息债务 / EBITDA | |
| 经营现金流 / 有息债务 | |
| 经营现金流 / 流动负债 | |
| 流动比率、速动比率 | |

- 利息支出取财务费用附注里的利息支出，不用财务费用净额。
- 资本化利息取在建工程等附注中的“借款费用资本化金额”；找不到就标“资本化利息未披露，倍数可能偏高”。

**④ 受限资产**

- 来源：附注里的“所有权或使用权受到限制的资产”表。
- 按类别列出：货币资金、应收票据、存货、固定资产、无形资产、投资性房地产等；保留原文写的受限原因。
- 计算受限资产占总资产、占净资产的比例。
- 受限货币资金同时用于③的现金短债比。

**⑤ 对外担保与或有负债**

- 上市公司：取“重要事项”里的担保情况表，分三项：对外担保（不含对子公司）、对子公司担保、担保总额占净资产比例（原文披露值）。
- 合并口径下，对子公司的担保不计入对外风险敞口，单独列示。
- 非上市主体：附注“承诺及或有事项”多为文字。v1 由模型通过原文检索引用，标注“来自文字披露”，不进入数值计算。

**⑥ 关联往来与资金占用**

- 其他应收款前五名及其占比（附注表）。
- 关联方应收、应付余额（关联方交易附注）。
- 复用现有信号里其他应收款、预付款项占总资产比例的计算。

**⑦ 信用风险信号**

用于初筛，阈值沿用现有 `POLICY` 的写法，标明“项目经验阈值 v1，未经行业校准”：

| 信号 | 阈值 |
|---|---|
| 现金短债比 | < 1 |
| 短期有息债务占比 | > 50% |
| 受限资产 / 净资产 | > 30% |
| 对外担保（不含对子公司）/ 净资产 | > 20% |
| 有息债务 / EBITDA | > 5 |
| EBITDA 利息保障倍数 | < 2 |
| 经营现金流 | 为负，或同比下降超过 30% |
| 其他应收款前五名占比 | 偏高且对象为关联方 |

信号不是结论。回答里要沿用现有做法：结合原文解释和可能的替代原因来写。

### 2.3 报告模板

导出的“信用分析报告”按以下顺序组织，Excel 底稿按同样顺序分 sheet：

1. 主体与资料范围：主体名称、报告期、合并或母公司口径、所用文件和页码范围；
2. 有息债务与期限结构；
3. 偿债能力；
4. 现金流；
5. 受限资产与或有负债；
6. 关联往来；
7. 风险关注点（推论，需人工判断）；
8. 资料缺口：没找到的项目和已经查过的范围。

## 3. 不在 v1 做

- **城投专属指标**：政府补助依赖度、应收政府款项、土地资产占比、区域财政。放到 v2。
- 债券募集说明书和债券条款解析。
- 多主体对比和行业分位数。
- 外部评级、舆情、现金流预测。
- 任何形式的信用评级输出。

## 4. 实现

### 4.1 入库（建议 N3）

新增或补齐以下附注表的识别和标准指标，全部带页码：

| 表或项目 | 拟用指标 ID | 说明 |
|---|---|---|
| 一年内到期的非流动负债明细 | `current_portion_long_term_borrowings`、`current_portion_bonds_payable`、`current_portion_lease_liabilities` | 现有 `noncurrent_liabilities_due_within_one_year` 只有合计 |
| 所有权或使用权受到限制的资产 | `restricted_assets_<类别>`、`restricted_assets_total` | 受限原因以文本保留 |
| 货币资金附注中的受限部分 | `restricted_cash` | 优先取受限资产表里的货币资金行 |
| 担保情况表（重要事项） | `external_guarantees_total`、`guarantees_to_subsidiaries_total`、`guarantee_total_to_net_assets_disclosed` | 只针对上市公司 |
| 财务费用明细 | 沿用 `interest_expense`；新增 `capitalized_interest` | 资本化利息取在建工程等附注 |
| 现金流量表补充资料 | 沿用 `depreciation`、`amortization_intangibles`、`amortization_deferred_expenses`；新增 `depreciation_right_of_use_assets` | |
| 其他应收款前五名 | `other_receivables_top5_total`、`other_receivables_top5_share` | 保留单位名称和是否关联方 |

已入库的伊利、海尔只对这些表做增量处理，不重跑全部入库。动手前先和 main 协调暂停窗口，沿用以往的入库续跑流程。

### 4.2 底稿（建议 N2）

- 新建 `service/workpaper_credit.py`，提供 `credit_analysis(service, project, document_id=None, company=None, scope='consolidated', periods=None, debt_scope='both', _analysis=None)`。
- 复用现有工具：`AnalystData`、`calc`、`ratio`、`unknown`、`locators`。单元格格式和 `publish()` 保持一致，这样回答绑定（A1）可以直接引用这些数值。
- 在 `financial_workpaper` 的 builders 里注册 `credit_analysis`；同步更新 `tool-schema.json` 和 `mcp_payloads.py` 的精简输出。
- 单元测试用伊利、海尔的真实入库数据，外加构造的边界情况：一年内到期部分不拆分、无担保表、受限资产表缺失、负 EBITDA。

### 4.3 编排与交付（建议 main）

- **宿主预计算**（`server/workpaper-precompute.ts`）：问题里出现信用类关键词时，把 `credit_analysis` 的精简版加进预计算底稿。关键词有：偿债、有息债务、信用、担保、受限、到期、短债、再融资、违约、债券、EBITDA 保障。其他问题保持原样，避免影响已经评测过的股票分析效果，也避免上下文变长。
- **提示指令**（`server/financial-guidance.ts`）：加一段信用分析规则：
  - 写明窄口径还是宽口径；
  - 受限现金不进现金短债比的分子；
  - 合并口径下对子公司的担保单独列示；
  - 信号不是结论；
  - 不输出评级。
- **交付检查**：在现有逐句检查里加一条：拦截评级符号（AAA 到 C 级）和“评级为”“可给予……评级”之类的表述，退回修改一次，沿用现有的修复与降级机制。
- **报告导出**（`service/report_package.py`）：按 2.3 的章节顺序加 `report_section` 映射和“信用分析报告”模板。

## 5. 样例与评测（建议 N1）

- **开发公司**：伊利 2024、海尔 2024，二者都已入库。另需**一家典型的信用研究对象**，由用户选定：负债高、有存续债券、附注里有受限资产和担保披露的上市公司比较合适。下载年报前要得到用户同意。
- **禁止使用的材料**：青岛啤酒、白云机场两个封存材料；美的 2024 作为扩展候选，也先不用。
- **题目**：6 道，覆盖 2.2 的 ①③④⑤⑦ 和一道综合题“这家公司的主要信用风险在哪”。
- **参考答案**：N1 根据 PDF 手工建立，每个数带页码。要做两遍独立核对，避免一个人出错。
- **怎么比**：只在这 6 题上比较金融智能体和原版 Pi，每组每题跑 2 次，控制 luna 的用量。统计四项：
  1. 已披露项目的数值是否全部正确，要求 100%；
  2. 每个数是否都有页码；
  3. 缺失项是否如实说明、没有编数；
  4. 是否出现评级表述，要求 0 次。
- **回归**：用伊利现有的 2 道股票分析题做冒烟测试，确认没有关键词时底稿和回答都不变。
