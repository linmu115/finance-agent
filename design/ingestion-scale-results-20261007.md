# N3 入库规模迭代：实现、实测与未通过项

2026-10-07 至 2026-10-08；基线 `ece4f21`，分支 `feat/ingestion-scale`。范围为 spec 验收 1、2。

## 结论

**整体验收未通过。** 自动续跑、结构分组、按表保留失败、来源及结果瘦身、语义遗漏诊断、主体证据候选均已实现。实际运行证明可以跨多次模型主动结束自动推进，并复用 Pi 原生压缩；但没有证明 CPA gpt-6-luna / low 能稳定完成高质量完整入库，也没有证明同质量单位成本显著下降。

中间版本瑞和一次达到 50/50，却留下 312 个待核验单元格；包含最终 SDK 修复的独立重跑只有 4/50，之后一次续跑无提交推进，按 spec 停为失败。小研报完成 13/13 和正文 3/3，但还有 47 个待核验单元格。伊利子集完成 51/51，仍有指标命名、会计准则口径和待核验缺口。**处理覆盖、原格回放正确、财务语义完整是三个不同结论。**

A 系列回归优先核查已执行：同一 3 页研报在 `2fd4ddf` 和当前主线源码都提前结束，没有证据把本次停止归因为 A0/A1/A1b；被观察的当前组和原 3001 样本都没有触发 A1 消息绑定/修复。详见 [回归对照](ingestion-regression-20261007.md)。不据此排除其他条件下的回归或提供商/依赖漂移。

## 环境与实验口径

- 全部在 worktree 下 `tmp/` 的独立数据目录，新项目、新 Pi 会话；真实 CPA gpt-6-luna，普通清洗 low，实际脚本/映射问题的下一次局部修复 high。
- RunManager → Pi → MCP stdio → 现有 Docker 沙箱。测量 harness 禁用脚本路径未使用的 LangExtract HTTP 桥；没有新 HTTP 端口，没有操作 3001，没有关闭 Docker。
- 每个独立 trial 的人工“继续”为 0。开发中重新开始的 trial 分列，不能把多轮研发拼成一次无人值守成功。没有向模型提供人工清洗脚本或样本答案。
- 瑞和：同一 57 页 PDF，56 张解析表、50 张数值候选表。历史 10-05 的 106 次请求、677 条事实使用 DeepSeek，仅作背景，不是本轮同模型基线。
- 小研报：用户新增明确授权的光大证券 2024-11-04 伊利点评，原项目 `374beac2`、文档 `47d2d1bad23d4318bdfa197bcad17349`，3 页、13 张候选表。仅使用获准的准备报告、该样本审计及原 PDF，没有读取 held-out 项目或其他 N1 评测材料。
- 规模材料：已提交旧版伊利 2024 原 PDF 的物理页 1–5、149–180，共 37 页、51 张候选表。子集在运行前确定；页码对应保存在 `tmp/scale-source/page-map.json`。没有执行整份 270 页入库。
- 请求分类使用实际 payload 字符数；不假称这些字符分项是精确 tokenizer token。用量来自 provider usage，输出中的 reasoning 是其细分，不再次加总。审计、payload、Pi 事件、脚本及原格结果均保存在对应 trial 目录。

## 五个方向的改动与依据

1. **按进度续跑。** 基线真实模型 stop 后仍有 50/50 或 13/13 待办，宿主却 completed。现在使用 Pi 原生 `agent_before_settle` 追加后续消息和紧凑剩余工作，不另建模型循环；表、正文页及本次修复候选都计入进度。取消/错误不继续，一次续跑无提交推进明确 failed。恢复时重新取持久进度，不仅凭最后 assistant stop 判断完成。实际见 12/14 次自动续跑及原生压缩；仍不能保证模型下一次行动正确。
2. **结构分批。** 章节、表头模式、列数分组，表/页上下文实际字符量参与预算；瑞和 50 单表批变为 32 批，子集 51 变为 43。单表超过预算仍完整返回，不静默截断。合法表可独立提交，已知失败批让未尝试批先行。实测一份脚本覆盖 5 张伊利表；SDK 计数错误原先会使整脚本丢失有效结果，现 map_table/map_series 的已知 MappingError 明确保留为该表失败，后续表继续；非预期 Python 错误仍按原错误失败。
3. **上下文瘦身。** 基线最后请求 176,800 字符：系统 7,620、工具定义 35,309、来源 9,349、历史结果 110,269、用户/助手历史 14,253。历史结果约占 62%。去除 stdout/stderr 与诊断日志重复、完整映射/样本默认回传、逐格重复几何元数据、每次 commit 的累计疑点；保留全原行、合并格、当前错误和完整按需读取。来源行显式编号，减少实测的多次行号猜错。短本地脚本直接返回 ready 摘要，瑞和 get_cleaning_result 从 7 次降为最终重跑 1 次；小研报改后 0 次。没有按历史年龄删除必要证据。
4. **语义映射完整性。** 实测发现 Revenue 组标题错配分项、列级 amount 覆盖行财务指标、含小数的文本列被 skip_columns 排除、第二次同表映射覆盖第一次期间。增加对应确定性诊断；比例/增长率/百分点/变动额有类型与单位；真正无法判断的原格作为明确待核验项保存。新规则对已有持久映射确定性重算，只让受影响表重新待处理，不抹掉旧事实或让模型重读所有有效旧表。SDK map_series/packed_row 负责原坐标配对，破折号保留逻辑位置但不变成零，共用 skip_rows 不再被修改。
5. **主体识别。** 从原文封面、释义、页眉等提取名称/代码候选，错误包含可直接用的逐字证据；允许主体名和证券代码分处多条原文证据，缺失交易所不猜。瑞和 set_document_profile 由基线 5 次变为最终重跑 2 次，小研报主线组 4 次、改后 3 次。并未彻底消除模型错误选证据。

对同一批已保存真实工具结果离线套用最终投影：基线 get_cleaning_result 57,402 → 20,711 字符；瑞和 v5 当时已发生的 23 次 commit 累计 817,886 → 81,703 字符（约减少90%）。这是相同结果的序列化投影测量，**不是实际账单或整轮成本下降90%**。原始记录为 `tmp/projection-replay.json`。最终瑞和重跑最后 payload 为 139,569 字符，其中历史结果 54,763，仍有工具定义 36,187 和来源 19,362。

## 原格回放与原 PDF 抽查

- 原格回放逐条验证 raw_value 与源单元格完全一致；有 numeric_span 时核对原串切片及偏移。它证明来源与数字搬运，不证明财务含义正确。
- 最终瑞和已存 16 条：PDF 物理页 12、14，16/16 的数值、正负、期间、单位和指标含义一致。页 33 说明 IFRS。全文件仍有 46 张表未提交，不能由这个小样本推断覆盖完整。
- 改后小研报首页 8 行×5 年的 40 条数值记录：40/40 数值、期间、百万元/每股/比例单位、A/E 类型一致；scope 为 unspecified，没有伪造会计准则。未覆盖的复杂预测原格仍是待核验。
- 伊利子集物理页 7、9（原 PDF 页 150、152）抽查 46 条：46/46 数值、期间、单位与 PDF 一致；因为全部被标成 IFRS，含会计口径的完整语义验收为 0/46。其中页 7 的 24 条还存在通用 amount ID。
- 保留负面中间结果：瑞和 v2 原格回放 16/16，但其中 10 条收入映射错位，语义仅 6/16 正确；v3 修好已存收入含义（13/13），却漏了现金流一个期间。v5 股东表的比例列被跳过，后补了 skipped_numeric_data_column 诊断。不能仅拿回放一致率做质量结论。

渲染与抽查文件在 `tmp/source-review/`，每轮完整 `facts.json`、`research-records.json`、`raw-cell-replay.json` 在 trial 目录。

## 验证、版本和边界

- 最后相关验证：75 个 Python 测试、12 个 Node 测试、服务 TypeScript 类型检查通过。覆盖实际坐标/比例遗漏、跨页主体证据、保存后复用、规则变化重检、按表失败隔离、破折号配对、共享参数不被修改、原生续跑进度计算与无损来源投影。
- 为遵守不开 HTTP 端口，没有运行依赖 HTTP mock server 的旧集成测试；真实 stdio/Pi/Docker 调用承担端到端证据。本轮未做 3001 浏览器上线验收。
- 中间长跑使用当时进程已加载版本，开发中没有替换它们动态读取的 SDK。最终 SDK 的独立瑞和运行使用 `tmp/final-code` 冻结源码（fa6a12c 加按表 SDK 错误保留与破折号修复），其原始请求及沙箱 SDK 均留存。之后仅收敛了示例会计口径和直接提交说明，未再次全规模重跑这些提示修订。
- 原计划第2步没有取得通过结果；本轮追加了由实测驱动的 SDK 修复及口径提示修订。分组与投影已有直接测量收益，整体完成率、完整财务语义和同质量单位成本仍待解决。不得把中间版本的高覆盖拼到最终代码上作为通过证据。
- 伊利 270 页整份入库、与旧库 4617 事实比较、held-out 续跑仍未执行，等待主线后续安排。主线合并重点检查 `server/runs.ts`、`server/model-context.ts`、`service/script_cleaning.py` 与同期 A 系列冲突；分支没有包含主目录后续未提交改动。

## 复跑入口
