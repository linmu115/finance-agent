# 按表搁置与既有事实替代

本轮已授权在 feat/ingestion-scale 实现五项修复，并以伊利、海尔的复制数据做零模型确定性验收。主目录、3001、Docker、held-out 和其他会话不在操作范围；生产数据只按两份明确文档 ID 只读复制。

已确认的问题：宿主在一次 Pi 收尾没有提交时停止整份文档；队列只把脚本失败表排后，未持久搁置。证券代码等只按少数首列标签排除。跨表比较没有充分表达小计/明细、资产/负债及关联方维度。原表查询只接受完整 ID。旧事实替换依赖相同 table_id 和行号，旧格式来源及准则后缀可能残留。

实施边界：继续使用 Pi agent_before_settle；程序在收尾更新表级搁置和候选队列，不新增 LLM 确认调用。普通队列耗尽后仅一轮搁置表 high 修复，停止时保留证据和未完成清单。搁置不算完成，失败不改成零。标识排除须依赖原格及行/列标签，t87 付息金额继续拦截。真正跨表冲突继续拦截。重提交以原表为替代范围，旧值归档；准则按本文档判定重新应用，历史保留。

## 实现

沿用 Pi 的 `agent_before_settle`，调用宿主专用 `advance_cleaning_round`。服务刷新真实提交账本，将本轮已提供或尝试但未提交的表搁置，保存错误、原格、来源标题和执行日志。已提交表从本轮尝试集合移除。没有接触过的表仍可选中；真实跨表冲突只退回冲突双方。程序自动映射失败也按表进入搁置集合。

普通队列耗尽后对搁置集合做一遍集中修复，结构分批与 Pi 会话机制不变，推理级别设 high。修复用的脚本输入只包含这批搁置表；修复失败的表标记已尝试，不再重新排入本次修复。所有可处理表用尽后停止并输出搁置清单。这里的一轮修复是覆盖搁置集合的一遍，各表各一次；一张修复失败仍不阻断其余待修表。没有新增模型核验请求、总工具调用上限或按表审批。

标识数字按邻接标签、列头和日期形态确定性识别，支持公司信息中的多组键值和多行表头。标识表的具体原格和原因写入排除记录，仍经过同一套校验与提交。金额文字、带物理单位的数据不能因同表存在序号而排除。

表查询、脚本 SDK、候选映射和提交选择均接受数字、`t`、`T` 别名；不接受其他文档的完整 ID。无法查到时返回当前文档/候选结果中的可用表标识。

新增维度直接取自源表：关联方列、同指标合计与组成项、表前资产/负债章节。维度和证据写入事实，而非只在比较时忽略冲突。正负号不同仅在原文明确声明相反呈现规则时视为相容。整表重新提交以该表为替代范围，旧表别名、旧表头行和未解决的旧事实归档；旧批次保留并标被取代。恢复入库时重新应用本文档已确定的准则和源文维度；每次提交也应用准则，已有旧解释归档，未知准则不猜测。
