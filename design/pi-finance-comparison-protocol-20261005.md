# 同模型 Pi 金融能力对照：开发试跑方案

> 历史试跑协议。后续用户已纠正成本口径：入库必须单列，不计入纯分析比较。新实验采用[三组、分账协议](pi-finance-analysis-protocol-20261005.md)。下文保留当时执行方式及其局限，不再作为下一轮的费用比较依据。

状态：2026-10-05 两组各三项真实任务及评审已完成，见[实验补充](../paper/experiments/pi-pilot-20261005.md)。用户授权本次临时启用沙箱并在结束后关闭；现已关闭 Docker/WSL，恢复原配置。正式重复实验与留出样本另行规划。此前“费用上限待确认”已由用户开始试验的授权替代。

## 研究问题与边界

保持 Pi 与模型提供商不变，比较通用文档/Python 工具与本项目金融工具、技能、结构化记录、核验和图表指导所带来的整体差异。这是完整系统比较，不把差异单独归因于某条提示词。正式实验再使用未参与开发的资料；当前两篇材料已反复用于开发，只能作为开发试跑。

| 分组 | 提供的能力 | 起始状态 |
| --- | --- | --- |
| A：通用 Pi | 相同原文解析、页/表/全文检索、隔离 Python、可下载产物 | 新项目、新会话、原始 PDF；无专用金融技能、清洗结果和图表主题 |
| B：金融项目 | 同一 Pi 与模型，加现有金融清洗、研究记录、模型、来源管理、技能和检查 | 另一个新项目、新会话、相同原始 PDF |

使用既有 `evaluation.profile=generic/financial`，不另建循环或端口。两组均使用 3001、相同单请求上限和允许的推理级别；保存每次实际路由，不能把“配置相同”写成“每次思考消耗相同”。主比较包含从原始材料开始的全部模型成本；已入库复用另列，不能拿 B 的复用成本对比 A 的首次读取。

## 共同任务（冻结后两组逐字相同）

1. 财报：根据瑞和数智 2025 中期报告，比较本期与同期的收入、毛利率、经营利润、净利润及经营现金流，解释利润与现金流的主要差异。给出可以从原文验证的数值、单位、期间、主体和页码；不重复扣除已计入费用汇总的财务费用。对不能确认的项目保留缺口，说明它只影响哪些结论。提供必要图表、所用数据和可复算脚本。
2. 研报：根据国信证券 2025-07-16 伊利股份报告，区分实际值、机构预测、观点与风险，列出报告提供的预测收入、利润及每股收益，保留机构、日期和预测期间。解释预测依赖的经营假设，并核对报告中可核对的估值勾稽。提供必要图表和数据，不把有限期预测当成已经实现的事实。
3. 建模：仅基于第二篇报告可核实的伊利数据，建立可复算的现金流估值与敏感性情景。缺少的净债务、股数或其他关键输入不得编造；可明确使用情景假设，或报告尚不能可靠计算的结果。终值参数须区分来源陈述与本次外推用途。给出简洁解释、关键假设、敏感性图和完整输入/计算产物。

第 3 项不能使用瑞和的数据填补伊利输入。相同任务中，是否主动找到缺口、作合理局部复核和保留限制均计入评分。问题和评分样本在运行前冻结；试跑中补充提示或纠错必须记为人工介入。共同限定只用提供的资料，不联网。每组一个新会话，财报任务附财报、研报任务附研报、建模任务复用本组研报；顺序为 A1、B1、B2、A2、A3、B3，串行运行以控制内存。首个任务两组均是原始文件起点；任务 2/3 包含各自前文，按任务同时报告增量与累计成本。

## 开始条件与运行记录

- 用 `node scripts/prepare-pi-comparison.mjs` 只读核实材料摘要、当前模型配置及实现指纹，生成准备清单。该脚本不创建会话、不发模型请求，不启动隔离服务。
- 两组任意脚本执行必须有相同可用的隔离环境。用户授权本次临时启动 WSL/Docker，并要求结束关闭；模型代码仅在相同隔离环境执行。独立复现实验须遵守届时有效的环境授权，不能用宿主代替沙箱。
- 用户已授权本轮试跑。使用既有实验接口，每道配对任务分别记录相同的宽裕技术保护额度，保存实际值及是否触发；费用仍按每组所有任务累计，不使先前入库消耗压缩后一道题的技术额度。这不是要求用户确认的人民币收费，也不修改正常会话限制。现有输入额度在返回 usage 后记账，不能承诺精确按人民币截断；未知用量不作零费用。发现异常重复、额度不足或持续基础设施失败时保留失败记录，不盲目付费重跑。
- 每组分别保存项目、会话、run ID；POST 结果不明时先检查已有会话与 run，不直接重复发送。发生自动重试、压缩、预算中止、权限等待或工具失败都记录。
- 同一比较中不自动改用 CPA 或另一个模型。确需切换，另起匹配的两组并保留失败结果，不能混算。
- 保存代码文件 SHA256（含未提交文件）、lockfile、模型/配置、两份 PDF 摘要、任务文本、启用技能/项目规则、实际路由与审计。两组交错/平衡顺序；不宣称能控制提供商缓存冷热，只报告实测。

## 评分与论文材料

运行前在单独的评审文件中人工核对原 PDF，冻结抽样题目、页码、精确值和容差；评分文件不给模型。每个任务记录下列字段，未评审填 `null`，失败保留。

| 维度 | 判定与分母 |
| --- | --- |
| 任务完成 | 逐项检查用户要求的交付物；说明原因的不可计算项与无解释漏项分开 |
| 数据正确 | 预标注样本的数值、单位、期间、主体、实际/预测身份分别评分；列出样本数，不冒充全文准确率 |
| 金融逻辑 | 财务费用范围、利润勾稽、现金流定义、假设合理性、终值外推、企业价值到股权价值逐项人工复核 |
| 证据 | 来源页/区域可定位、文字匹配、来源真的支持结论分别记录 |
| 可复算 | 用冻结输入重算结果，核对图与数据；不以“生成了文件”代替计算一致 |
| 表达 | 结论清楚、必要图表可读、关键限制可见；内部检查日志不挤占解释 |
| 成本 | 全部请求的输入、缓存输入、输出、思考、未知用量、耗时、干预；思考若包含于输出，不重复相加 |

缓存命中率 = 所有已知缓存输入之和 / 对应已知输入之和，同时展示缓存统计覆盖了多少输入。费用同时保留计价来源、币种、价格有效时间和估算/账单身份。
