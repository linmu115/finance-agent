## 根因与修复

`signals` / `signals_signals` 最长定位单元格为 12,956 字符，驱动证据接近 2,000 字符。原实现将定位 JSON 和任意长度表格直接交给 `fitz.Story.write()`。完整报告限时 5 秒复现零字节 PDF（`before-full.json`）；最长单行单独渲染却能完成（`before.json`），因此不是简单的字符数阈值。

诊断还复现了缩短单元格后 Story 重复分页；只加文本上限不足。最终 PDF 将所有表格转换为纯文本单元格，正文上限 120 字符、表头 48 字符；每组最多 4 列、每段最多 4 个数据行，重复表头和首列标识。表格不再让原生布局引擎处理跨越多页的大块内容。Markdown 表格单元格上限 240 字符。定位改为文档、页码和处数，并注明完整内容见底稿/快照；方向提示中带有转义竖线的定位也转换为摘要。

渲染在独立子进程完成，标准输入设为 DEVNULL，避免继承 MCP 输入管道；25 秒到期真正终止渲染并回收子进程，不留下后台 CPU/内存任务。先写临时 PDF，成功后原子替换，失败保留其余交付文件并清理半成品。宿主同会话复用同一 Promise，Python 渲染入口同时拒绝同会话的重复渲染。
