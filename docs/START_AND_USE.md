# Finance Agent 0.4.0：服务启动与使用 README

适用环境：Windows 10/11 x64，单用户本机运行。页面统一为 **http://127.0.0.1:3001/**。本指南对应本地发布候选 `v0.4.0`（产品能力为 F2.1）；安装包、源代码和当前运行进程是三个不同对象，下载或更新代码不会自动替换已经运行的旧进程。

## 1. 下载与安装

取得本次提供的 `finance-agent-0.4.0-windows-x64.zip` 和 `SHA256SUMS.txt`。本版尚未发布 GitHub Release。

GitHub 自动生成的 Source code ZIP 不含运行环境；普通使用请选上面的 Windows 部署 ZIP。部署包包含 Node.js 24.7.0、Python 3.12.11、生产依赖、构建后的前后端、中文文档和用于解析验证的历史公开 PDF 小样，不要求另装 Node、Python 或 Excel。Docker 引擎及计算镜像需要另行准备。

可在 PowerShell 核对下载文件：

```powershell
Get-FileHash .\finance-agent-0.4.0-windows-x64.zip -Algorithm SHA256
```

将结果与同批提供的校验文件比较。完整解压到可写目录，例如 `D:\Apps\FinanceAgent-0.4.0`，不要在压缩包预览窗口运行。建议至少预留 3 GB 空间，再为资料和计算结果留额外空间。

确认旧实例已停止后，双击 `install.cmd`。它检查内置环境、创建当前用户桌面快捷方式、启动本机服务并打开页面。无需管理员权限，不修改系统 PATH，不注册 Windows 服务或开机自启，不自动启动 Docker/WSL。

首次运行最多等待 3 分钟，避免反复双击。页面打开后在“API 配置”中保存自己的设置。

## 2. 启动、检查与停止

| 入口 | 作用 |
|---|---|
| `install.cmd` | 首次检查、创建快捷方式并启动 |
| `start-finance.cmd` | 日常启动；复用本安装目录已启动的健康实例 |
| `check-install.cmd` | 检查运行环境、依赖、数据目录和服务状态 |
| `stop-finance.cmd` | 停止由本安装启动器登记的实例，保留数据 |

也可在安装目录运行：

```powershell
.\check-install.cmd
.\start-finance.cmd
```

用完后先等待任务完成，或在会话中停止任务、处理待授权请求，再运行：

```powershell
.\stop-finance.cmd
```

关闭浏览器只关闭页面，后台服务仍运行。启动器会核对进程的启动时间、可执行路径和所属目录，不按“node.exe”名称批量结束进程。端口冲突时先确认旧实例归属再停止，不通过另开 3002/3003 规避。

健康检查地址为 `/api/health`。新版成功启动时应返回 `ok: true`、`service: "connected"`、`version: "0.4.0"`。`modelConfigured` 表示填过模型 ID，不证明密钥、余额或上游模型可用。

如果旧进程由开发命令启动，便携启动器可能因缺少自己的进程登记而拒绝接管；应回到原启动终端停止，或由操作者核对进程后停止。不要为了消除端口提示删除未知 PID 文件或结束全部 Node/Python 进程。

## 3. API 与计算环境

在“API 配置”中保存模型提供商、模型 ID、地址和密钥，再执行“测试连接”。支持 Pi 全局模型目录，以及应用内的 OpenAI 兼容配置；选择具体模型时必须以自己的服务商实际可用 ID 为准。开发验收使用 `deepseek-flash`，但部署包不附带账号和密钥。

Tavily/Brave 用于联网检索；不用联网研究时可以不配。Embedding 默认关闭，关键词与结构化查询仍可用；启用后会产生另行的向量服务用量。本地 OCR 随包提供，扫描质量仍会影响解析效果。

默认脚本清洗和任意 Python 分析需要已启动的 Linux Docker 引擎及 `finance-analysis:0.1` 镜像：

```powershell
.\runtime\python\python.exe .\sandbox\download_wheels.py
docker build -t finance-analysis:0.1 .\sandbox
```

镜像标签独立于应用版本，本版继续使用上述标签。首次下载和构建需要网络。没有沙箱时工具会报告不可用，不会改成直接在宿主运行模型生成的代码。查询已保存资料、内置公式与固定金融模型工具不依赖 Docker。详细资源限制见 [沙箱说明](../sandbox/README.md)。

## 4. 一次完整研究的操作顺序

1. 新建公司或研究主题项目。项目下展开/收起会话；同项目共享数据，各会话有自己的任务过程。
2. 在会话添加 PDF、Excel、CSV 或 TSV，并发送任务。上传只保存附件，发送后才开始处理。
3. 用右上角 **附件流向** 查看当前会话的处理进度、已完成资料、提取信息和数据库去向。点来源查看 PDF 页或原表；“处理完成”和“核验通过”分开显示。
4. 进入左侧 **资产看板**，选择研究对象。财务与经营看正式披露；机构预期看研报预测及发布日期；观点与证据看归属与原句；模型与成果看保存的计算结果和版本。没有保存成果时模型页为空是正常状态，入库不会凭空生成 DCF。
5. 选中看板记录，点击“就此分析”会生成带来源的会话草稿；确认问题后再发送。会话正文也可划选引用、写批注、多段引用一起发送。
6. 在项目设置维护 `agent.md` 和启用的金融技能。普通清洗最低 low，复杂疑点允许 high；建模使用更充分推理。具体是否支持该参数由所选提供商与模型决定。
7. 任务执行中可继续输入：Enter 补充当前任务，Alt+Enter 排队到当前任务之后。停止只作用于对应会话。
8. 已完成回复下方的小字展示输入、输出、缓存命中与比例，展开可看阶段、思考和费用。思考属于输出子集；费用是按设置估算，未知用量不会当作零。

财报主要保存披露事实；研报保存机构、作者、发布日期、预测版本、多公司/行业数值与观点。同一张研报表只做一次映射，历史引用和预测按记录性质分流，不重复跑整份财报流程。对预测提问时明确“截至哪一天”。

### 附件看板与资料删除

左侧“附件看板”列出当前项目已登记的财报、研报及其他附件，包含原始文件名、类型、机构、登记日期、处理状态、财务事实及研报记录数。上传但尚未处理的资料会标为待处理。可以搜索文件名或机构，点击原文进入右侧查看。

每行“删除”先展开确认信息；点击“确认删除”后清除该资料的原件副本、原文解析、当前及历史入库数据、预测/观点、检索条目、处理快照与关联计算产物。删除不会只隐藏列表项。其他附件数据保留，删除后重新上传会建立新的资料身份。当前项目有运行中任务时，先完成或停止任务再删除。

此操作不能在看板中撤销。历史会话文字和已有备份保留；已保存模型不自动重算，会标记引用来源缺失。附件流向仍记录当前会话处理过程，附件看板管理项目资料清单；原“数据集与测试”导航已移除，历史测试资料与脚本仍在源码仓库保留。

### “观点与证据”看什么

它是研报中的定性记录列表，例如增长判断、经营风险、催化因素或管理层表述，附原文依据、归属机构/说话者、报告日期和页码。可按对象、机构、日期、关键词和质量状态筛选，查看原文，并选中多条带入会话提问。“机构预期”主要看预测数值，“模型与成果”看保存的计算模型和研究报告。观点有出处不等于观点真实或已经发生；待核验标记需要结合本次任务判断影响。

## 5. 可直接复制的验收任务

先上传一份自己合法取得的上市公司财报：

> 完整处理这份财报，包括主表、附注和分部资料。保存原文坐标、期间、币种单位和合并口径；不确定的内容标记待核验。完成后报告候选表处理覆盖、入库数量和仍未解决的问题，不要把处理完成说成全部核验通过。

入库后在同一项目新会话提问：

> 比较最近两个可比期间的收入、毛利、净利润和经营现金流，解释利润与现金流差异。保存现金桥底稿和图表，区分披露事实、量化影响与推论，每项结论给出来源。

再上传一份研报：

> 按研报处理全部表格与正文，登记机构、作者、发布日期和研究对象。区分引用实际值、盈利预测、行业统计和观点；保留证据原句与预测版本，不写入公司的正式披露事实。

建模任务：

> 仅使用这份研报发表时可见的信息演示 FCFF DCF，明确估值时点。将来源数值、计算值和额外假设分别列出；保存 WACC 8% 与 10% 两个情景，其他输入保持一致，检查 EBIT、营运资本、终值和企业价值到股权价值的桥接。数据不足时说明缺项，不编造披露。

包内 `benchmark/versions/v0.5-holdout/inputs/cnooc_2025_en_whole_tables.pdf` 是历史公开解析小样，用于安装验收，不是本轮封存测试材料；完整研究材料由使用者自行提供。

## 6. 授权与数据保护

普通工具绑定当前项目。任意 SQL/DDL、破坏性删改、跨项目访问及分析代码请求直接修改主数据库等受控操作，每次展示输入框上方的授权卡片。正常入库仍走已授权任务中的专用提交工具。核对操作、理由和参数再决定；Enter 只在允许的焦点状态同意，中文输入法选词或输入消息时不应误触。项目约定可以补充研究规则，不能替代后端权限校验。

默认沙箱断网、输入只读，不挂载主数据库和 API 密钥。申请获准的高权限操作通过宿主受控通道执行，不因模型写了脚本就获得无限制宿主权限。

实际数据默认位于 `data/active/`，包括 `finance.sqlite`、上传原件、会话、模型、审计、配置等。日志在 `data/active/runtime/`。Windows 密钥使用当前用户 DPAPI 加密；数据库和上传资料并非整体加密，仍需使用操作系统权限及可靠备份。

## 从 0.1 或当前开发目录升级

1. 等待/停止会话任务，解决待授权项，使用原实例对应的方式停止服务。
2. 找到实际数据库位置：v0.1 常见为 `data/finance.sqlite`，新版开发目录常见为 `data/active/finance.sqlite`；自定义 `FINANCE_DATA_DIR` 时以该目录为准。不要把多个历史测试库合并到一个目录。
3. 在服务停止后复制整个实际数据目录到备份位置，包含数据库及其他文件。不要只复制 SQLite 主文件而漏掉 WAL、原件或成果。
4. 解压 v0.4.0 到新目录，把要继续使用的旧数据目录的**内容**复制到新安装的 `data/active/`。若使用自定义数据路径，启动和停止均传相同 `-DataDirectory`。
5. 同一 Windows 用户可保留 DPAPI 配置；跨电脑或用户需重新填写密钥。旧备份保留，以便回退。
6. 在 3001 启动新版，核对健康版本、项目、会话、原文与成果。新增数据结构由服务初始化；不要再让旧程序对升级后的同一个数据目录写入。回退应使用升级前备份。

当前开发机已有验收数据，而发布包是无个人数据的全新安装。包内不会预先出现开发机的项目和会话；使用上面的任务可自行体验流程。论文与评测汇总独立于部署包交付，不分发原始对话和密钥。

## 7. 故障排查

| 现象 | 检查与处理 |
|---|---|
| 3001 已被占用 | 确认旧实例；不要同时启动源码版与便携版 |
| 检查提示缺文件 | 确认完整解压 Windows ZIP，未误下 Source code |
| 401、402 或模型不可用 | 核对已保存配置、余额与服务商模型 ID；不要反复重发结果未知的写操作 |
| Docker 不可用 | 启动引擎、准备镜像，再从会话检查点继续；不在宿主绕开沙箱 |
| 长任务中断 | 查看任务错误与附件流向；已提交批次可从检查点继续，断网或余额不足不会被标成成功 |
| 看板为空 | 检查所选项目/研究对象；上传不等于入库，入库不等于已保存模型 |
| 处理完成但有疑点 | 查看待核验项目和原文，按具体表/页定向修复，不必重做整份资料 |
| 内存占用高 | 同时查看应用、容器和 WSL 占用；WSL 总量包含缓存，不直接等同泄漏。关闭不用的任务后观察，避免为解决单个应用而强制关闭全部 WSL |
| 启动窗口报错 | 查看 `data/active/runtime/server-3001.stderr.log`；反馈时删除密钥与私人资料 |

## 8. 从源码启动

需要 Node.js 24+、Python 3.12、Git 和依赖下载网络：

```powershell
git clone https://github.com/linmu115/finance-agent.git
cd finance-agent
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
npm ci
npm run build
.\start-finance.cmd
```

构建完成后只启动一个 3001 服务。不要删除本机全局 Pi 配置以解决应用问题；本应用的显式 API 覆盖只在自己的运行时生效。
