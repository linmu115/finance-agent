## 2 稳定性规则（替换原协议第 88 行的判定部分）

**原规则**：实质缺陷“有 / 无”必须逐案一致，适用维度的平均绝对差不超过 0.5、最大差不超过 1；达不到时，结论为“未证实”。

**为什么改**：
- 两批门槛各 18 案，一致率分别为 17/18 和 15/18。但两遍评审在“金融组 vs prepared”的质量和深度方向上**各自得出了相同结论**。
- F2.1 的 3 个分歧分别落在三组，每组 1 个，都是“单位混用算轻微还是实质”的严重度分歧，不偏向任何一组。
- 到 162 案时，两个独立 LLM 评审逐案完全一致在实践中几乎不可能。原规则会让结论取决于评审噪声，而不是系统之间的差异。

**新规则**：
1. **双遍独立成立。** 两个对比（financial vs original_pi、financial vs prepared）在两个子集（开发核心、held-out）上分别判定，每个判定在第一遍、倒序遍中各算一次：
   - 两遍都成立，记为“成立”；
   - 两遍都不成立，记为“不成立”；
   - 两遍结论不同，记为“两遍不一致，未证实”。
2. **可靠性下限（按子集计算）。** 必须同时满足以下两条：
   - 实质缺陷“有 / 无”的逐案一致率不低于 **80%**；
   - 适用维度的平均绝对差不超过 **0.5**。
   
   达不到下限时，该子集的全部结论记为“评审可靠性不足，未证实”，不论第 1 条结果如何。
3. **照实报告。** 以下内容全部公开：
   - 一致率、Cohen's κ；
   - 分歧在各组中的分布，用于检查是否对称；
   - 最大分差；
   - 全部分歧原文。
4. **不做事后处理。** 不对分歧案例追加裁决，不取两遍平均，不只挑其中一遍。原协议“不得追加裁决直到过关”继续有效。
5. **最大分差只报告，不作判定条件。**

**80% 下限的理由**：
- 低于这个水平，说明 rubric 对“实质缺陷”的界定本身不清，单遍结论也不可信；
- 两批门槛的实测值是 94% 和 83%，下限设在两者之下，又不至于形同虚设。

**防止挑选结果的约束**：
- 规则在开跑前写定并提交 git，正式评测期间不再修改；
- 不追加回合，也不追加评审；
- 两遍的原始评分全部公开；
- 门槛批次的结论不按新规则重新解释。

## 3 未知用量的处理

**原规则**：只要出现一次未知用量，成本项就判“不确定”。

**新规则**：成本按上下界计算。
- 下界：已知小计，未知请求按 0 计。
- 上界：每个未知请求，用同一批次、同组、同题中观测到的最大单次请求输入和输出来填补。
- 成本结论必须在上下界两种算法下都成立才算“成立”，否则记为“不确定”。上下界都要报告。

## 4 成本口径与表述

- **E4 主判据不变**：配对回合费用的中位数，以及总量披露。
- **补充指标**（原协议第 82 行已列出）：每个“完成且无实质缺陷”的回合所对应的已知输入，以及按目录价估算的费用。两遍分别计算。补充指标不能替代 E4 成本判据。
- **表述规则**：如果对原版 Pi 的成本判据不成立，报告和对外材料只能写成：“质量与深度领先；已知输入多 X%；每个无缺陷回答对应的输入为 Y（对原版为 Z）”。**不得写“更省”或“成本更低”。**
