## 3001 两组配置如何读取

两组是同一个 3001 上的**逐会话 evaluation profile**，不是两个端口、两个服务或来回改全局配置。

1. `GET /api/health`、`GET /api/settings`读取共同模型与运行设置；检查 provider=`cpa-local`、model=`gpt-6-luna`，保存可公开设置、价格来源状态和摘要，不落凭据。当前 `/api/settings` 的 runtime 为 120 秒请求超时、自动上下文压缩目标 96k/保留 24k；正式版重新读，不直接沿用此值。
2. 执行器为独立题新建 conversation；以 `POST /api/conversations/{id}/messages` 的 `evaluation.profile` 选择 `prepared` 或 `financial`。正文为冻结原题，`documentIds: []` 使用已准备资产，避免正式分析再触发入库。`evaluation.budget_group_id` 和 `budget`沿用产品评测接口。D3/H2复用本臂本次父会话，服务本身拒绝跨 profile 切换。
3. 两组都用当前产品原生推理路由：router low，analysis/modeling high，清洗 low、局部异常 high。保存每次 `reasoning_route`、`model_request` 的实际模型与发送强度；同代码不等于路由结果必然相同，有差异必须披露，不改产品提示强行补齐。
4. `/api/settings` **不返回两组完整提示和工具定义**。从主线的部署配置快照读取 profile 摘要；实际运行再保存 `run_config` 的 profile、configHash、promptHash、tools 及审计请求。当前快照 `data/evaluation/analyst-freeze-20261008/manifest.json` 显示 prepared 13 工具、financial 40 工具；它是候选部署证据，不是 N4 后的正式配置。最终需要项目实际 rules/skills/revision 与有效工具 schema 的快照，不能拿空测量项目替代。
5. 运行采集接口为 `GET /api/runs/{id}`、`GET /api/conversations/{id}` 与本地对应审计；所有 `posting` 先持久化。未知 POST 先核对原会话/运行号，不重新发送。

现有 `runner.mjs` 已支持上述 profile 请求、同会话更新、逐项目分页快照和基本代码/设置校验。它当前是**单项目顺序执行器**，尚未实现本方案的跨公司总调度、完整运行态冻结和成果隔离。批准方案后在评测台范围补齐调度/快照与离线验证；这次不把规划 JSON 当可运行正式配置。

## 评审、统计与 E4 门槛

程序先做数值/单位/方向/来源、全部仍交付产物下载及隔离复算；A5 使用主线实际扫描结果，不另写一个提示扫描器代替。A5 目前评测适配器仍是外部结果导入，需要最终结果契约与入口。复算成功只证明可重复，原格回放成功不证明语义正确。

匿名包保留回答、全部交付附件与版本关系、必要的程序核验观察；去除工具/路径/底稿身份，不改数值与图中数据。两遍使用独立随机编号，第二遍换序；私有解码映射、组别、用量和开发背景不交评审。每位评审只看本块匿名材料、rubric 和冻结参考，记录实际模型/强度、thread ID（不可得则 null）、已读图/未审文件和用量。第二遍不看第一遍结论。图内无法无损消除的身份痕迹需披露、修正包后统一评审，不能裁掉错误证据。当前隔离是任务/访问约束，不声称共享文件系统是 OS 级隔离。

沿用六维 v2：R1 阅读、R2 实质取数计算、R3 变动解释、R4 非经常/口径、R5 异常信号、C 结构化/追溯/事实推论观点。**任何实质错误，R2 最高 1 分**；未考查维度为 null，不算零分或满分。保存去重后的实质缺陷类别/证据位置，并同时报有实质缺陷的回合数，避免同一错误出现在三个附件就随意膨胀三倍。

先封存两遍评分再解盲；稳定性继续为实质缺陷有无逐案一致、有效维度平均绝对差≤0.5、单项最大差≤1。分歧保留；有无分歧或会影响门槛的分歧需匿名裁决/重审，不能取对金融组更有利的一遍。

按题、题型、split 和组列两次原始结果、各适用维度均分、实质缺陷数、完成率，以及成本中位数/区间和全部尝试总量。**沿用 spec E4：开发集与 held-out 必须各自同时满足实质缺陷不更多、专业深度更高、已知分析成本不更高，才可说“优于基线”。** 扩展集单列并报告负面结果，不能拿扩展平均抵消 held-out 失败。

v2 的“深度”沿用当前 `metrics.py` 的保守映射：R3/R4/R5在成对适用样本上的均分各自不低，且至少一维严格高；没有任何适用深度维度则不能满足。成本主口径沿用同 split 配对回合费用中位数（失败/重试成本累计到对应回合），同时检查/披露总费用及区间，不允许总成本更高却无条件宣传更便宜。参与者费用含完成该分析的全部路由、压缩、失败重试；准备资产支出不掺入分析比较。用量/费率未核实、配对不全、参评未完成、关键交付未评或换序结论不稳定，不能宣称优势；未知不是 0。小样本仅报告方向和一致性，不报告统计显著性，不推广到所有金融任务。
