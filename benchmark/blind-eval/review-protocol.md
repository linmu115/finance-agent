# 独立线程与冻结规则

评审模型固定 **gpt-6-astra**，思考强度 **high**。适用于历史演练和今后正式盲评，不使用参与分析的 gpt-6-luna 代替评审。

本环境使用 `collaboration.spawn_agent`，明确 `fork_turns="none"`, `model="gpt-6-astra"`, `reasoning_effort="high"`。每轮都是新线程，只收到单独 round 目录路径及评审任务，禁止访问包外文件、开发史、组别映射、另一轮评审和网络。首评与换序复评分别新建，不复用上下文。线程调用记录保存实际 canonical task name 和可取得的 thread id；拿不到实际 UUID 就留空，不伪造。模型/强度以显式工具调用记录为证。

输入：该轮 cases.json 的顺序；各 case 的题目、完整回答、所有交付附件和匿名代码；reference 内 rubric、参考答案及原页。不给预算、工具审计、原始路径、profile、版本提交、历史判语、已知错误分布。

输出：rubric 定义的 review.json。读图是评审任务的一部分。评审不能执行提交的代码。程序下载和沙箱复算另做；历史演练只继承历史下载/复算证据并标记时间，不冒充本轮重跑。

收集器的文件角色按实际交付区分：`delivered_attachment`为下载成功附件；`evaluator_copy_download_failed`是下载失败后取得的评审副本，能审内容但不得计作交付成功；`unavailable_attachment`保留失败状态和缺失，不能按零值处理；`evaluator_copy_not_delivery`为额外执行代码证据。对未成功交付的尝试与仍挂载旧版本分别判断，不把已修复且未交付的失败代码算作最终交付错误。

匿名化保留版本与缺失、金额、币种、年份、页码、计算代码及实质缺陷。路径与组件名替换；匿名代码不再保证可执行。原始代码保留供沙箱复算。图片保留原像素、改匿名文件名；若图内带组别标识需单独处理并登记，不能抹掉数字缺陷。文字扫描无命中仅证明未发现列出的显式模式，风格/能力差异仍可能让人推断来源。

只在两次评审提交后解码，与既有人工评审逐项比较。报告缺陷召回、额外发现、严重性分歧与未审范围。稳定性采用 rubric 已写好的阈值；不事后改阈值。

正式样本先经 Claude 审定题面和参考答案；按明确通知冻结主线版本、同资料快照、任务与参考、路由。准备费用单列，任何中断/失败都保留。评审支出属于评测开销，另外列账。未知账单不凭 token 或目录价格推算为确定费用。
