# v3 三组评测方案（已审；参评尚未开跑）

协调者已批准原版契约、18 回合门槛、新 held-out 题面/参考，并将正式规模调整为 162 回合。白云机场标准完整入库已获新授权并启动，用量单列；尚未运行付费参评。依据 `design/harness-v3-usable-depth-20261008.md`、已审 E4 和六维 v2 rubric。美的 2024 已被历史测试使用，降为扩展候选。新公司 held-out 的材料、题面和参考仅在 N1 私有目录，不能交主线、N2、N3、N4 调试。

## 两个需要分别回答的问题

1. **整套 harness vs 历史定义的原版 Pi**：financial − original_pi，差异包含结构化准备资产、交付/绑定基建、领域指导、金融计算/底稿及 v3 宿主预计算。
2. **金融层 vs prepared 的增量**：financial − prepared。P/F 使用相同事实快照、原文和共享 A0/A1/P2 基建；差异包含金融提示、工具、底稿和 P1.0 预计算，不能归因成某一个工具的纯因果效果。

prepared − original_pi 为辅助结果，用于看准备资产和共享基建整体贡献。三个结论不能互相替代。历史 A/H/B/X7 只有 prepared/financial，不能拿来声称已经完成原版 Pi 比较。

## 原版 Pi 的可复现定义与现有缺口

核查详见 `data/evaluation/blind-eval-v3-design-20261008/BASELINE_AUDIT.md`。2026-10-05 实际 generic 的系统提示 SHA256 为 `6c71fd727034260afcaa6e29e833ff27000cb7f246b2b0ffc83aa867be20c32f`，10 个原文/计算工具，不挂金融数据和领域资源。它是本项目历史“通用 Pi”配置，不是未经任何适配的上游 Pi CLI。历史本来就提供 PDF 原文解析、原页/原表读取、搜索、隔离 Python 和下载；不能现在撤掉这些基本能力削弱基线。

当前 generic 已挂共享交付与回答指导、A0 报告/类型单元格辅助、A1 绑定和修复路径，不能直接命名为原版。`analysis_only:true` 只关闭入库入口，不会关闭这些能力。

拟冻结 **original_pi = legacy generic v0.2 行为契约**：同一 v3 Pi 引擎、模型、原文解析、基础沙箱/字体/文件交付/审计；保留原 10 工具和原提示；不提供 facts/research_records、report/save_table、回答绑定/语义标注、估值检查、领域工具/图表模板/模型资产和金融宿主预计算。允许模型自行用普通 Python 库生成 PDF、CSV、图和报告，产物照常评分。工具的基础执行、项目/沙箱安全、输出文件下载和可执行代码留档属于三组共同基础设施；本项目的报告组织、数值绑定、修复、标注不属于 original_pi。

当前没有一个已验证的开关能满足此契约，**配置不是开箱即跑**。建议主线提供明确的评测专用 original_pi profile（仍走 3001、同一 Pi/沙箱版本）或等价评测适配入口；N1 只定义和验收契约，不越界修改产品。本轮 JSON 中 `original_pi` 是计划逻辑名，不是假装现有 API 枚举。不能通过回滚整个产品版本形成模型/运行时混杂，也不另开端口。落地后用离线请求捕获核对实际系统提示、工具 schema、沙箱挂载和宿主路径；禁止把 generic 的名字改一下就算完成。

## 样本与执行顺序

已批准开发核心与新 held-out 每题每组 **6 次**，覆盖三组 6 种排列：GPF、GFP、PGF、PFG、FGP、FPG。相对历史 2 次能减小单回合波动，但不是增加公司样本数。核心/held-out 每种排列每题用一次；已见扩展每组 3 次，用 GPF、PFG、FGP 拉丁方。按固定 seed 将题链排列顺序打散；不能看完结果后增加某组重复或挑一轮。

年报、半年报、季报读取在上述开发/扩展资料中分别覆盖；新 held-out 只有一份年报，不单独宣称已验证三个报告类型的跨公司泛化。逐题最终评分范围以冻结的 task_requirements 为准，不能因金融组额外调用底稿而增加得分维度。

D2→D3 在同一组、同一 repeat、同一 session/隔离键内连续执行，不插入另一组答案；各链间完全独立。三组顺序按链而非消息交错。每条链的隔离键含 freeze、split、task-chain、arm、repeat 和随机 run id，不复用历史键。所有回合/续题携带 `evaluation.analysis_only:true`、`documentIds:[]`，最多两条题链并发，同一时刻来自不同组；G/P、P/F、F/G 轮转组合。保留预定题链启动顺序，同组仍占槽时等待，不跳过队列。D2→D3 保持链内串行和会话；记录重叠运行、排队和端到端时间，耗时不是隔离条件下测得，不能等同组间纯计算速度。新 held-out 三题先设计为独立会话，避免依赖第一题提示答案。

同一材料字节/原始解析提供给三组，G 只读原文视图，P/F 共享一份准备视图。必需表在项目提交边界达到门槛后暂停写入，记录已提交/未完成/搁置表、语义限制；不能只看文档 completed 状态。缺一张必要表就明确相应题“资料未就绪”，不删除题后悄悄减少分母。

## 进度门槛：P0 + P1.0 + P2 后的 18 回合

配置见 `v3-gate-plan.json` 和 `v3-gate-schedule.json`（仅计划数据；没有提交）。D1 卡罗特、X3 伊利、X7 海尔，各 3 组 × 2 次 = 18 回合。第一遍三题分别 GPF/PFG/FGP，第二遍各自反转为 FPG/GFP/PGF；每组在每个位置出现 2 次。原题和冻结参考沿用，先重新冻结当次数据，不能沿用已被后续入库改变的旧摘要。

以下为协调者已批准的门槛数值标准：

- 两遍评审均要求 F 的实质缺陷回合至少比 P 少 2/6，且不超过 P 的 50%；去重缺陷条目数也不能更多。若 P 只有 0–1 个缺陷，报告地板效应/证据不足，不为过关改题。
- R3 在 D1/X3/X7 的配对适用样本均分 F≥P；R5 主考 D1/X3（4 个回合/组）均分 F≥P，X7 辅助分另列。完成率 F≥P。
- F 的全尝试已知总输入与配对回合输入中位数均≤P；任一组存在未知请求用量，成本门槛记“不确定”，不把下界判为省钱。输出和费用另报。
- 三组产品原因回合失败数为 0；基础设施失败保留且继续调度，但缺配对时门槛结果为证据不足。金融输入减少不能靠失败提前结束。
- 两遍盲评满足下述稳定性，且所有 mandatory 产物已审；否则不判通过。12–18 回合是工程进度判断，不声称统计显著。

通过后继续 P1 剩余/P3 和新 held-out；未通过先定位数据、工具、提示、宿主或交付问题，按 spec 不继续盲目加功能。一次门槛预算是 18 回合，不包含自动反复测到通过；如修复后再测，必须新 freeze/批次、旧失败留账。

## 指标、稳定性与优势门槛

沿用六维 v2（0–4）：R1 读取、R2 准确取数/计算、R3 解释业绩变化、R4 非经常损益/会计口径、R5 异常信号、C 结构化/可追溯/事实推论观点。**任何实质错误使 R2 最高 1 分**。题目未考查维度为 null；题别适用性在开跑前冻结。R3/R5 的直接主考与模型更新/估值辅助证据分别汇总。C 同时记录交付一致性、追溯/重放、事实/推论/观点与假设风险边界，不能只看附件存在。

每个对比各自适用 E4：开发核心与新 held-out 必须分别满足实质缺陷不更多、专业深度更高、分析成本不更高。深度沿用 R3/R4/R5 配对适用均分均不低且至少一维严格更高；扩展集单列，不能抵消 held-out 失败。另列 v3 R3/R5 相对旧轮的方向和 ≥0.5 分目标，但跨版本/数据变化只作描述，不能当同期对照。新三组正式比较必须同一个冻结版本。

费用 E4 使用已核实同价口径的配对回合费用中位数，失败/宿主重试全计入，并披露总量；总费用更高不能无条件称更便宜。原版/金融、prepared/金融分别判，不能一个通过就同时写两个优势结论。用量/费率未知、参评未完成、评审不稳定或关键交付未审时，结论为未证实。

质量同时给出：无实质错误且完成的回合率、缺陷回合/去重条目/类别、六维配对差、完成率及失败原因、程序选择器命中率和原页核验。效能给：请求数、已知输入/未缓存/缓存读写、输出/reasoning、各阶段用量、端到端/首有效交付时间、交付可打开/可重放率、每成功且无实质缺陷回合成本。reasoning 不重复累加输出；重放不是语义正确证明。A5 只接现有 CLI 结果，不另写扫描器冒充它。

统计单位先按题对已批准的 6 次（核心/held-out）或 3 次（扩展）重复汇总，再在各 split 内做题级配对，不把同公司重复当独立公司。报告全部重复、均值/中位数/范围、配对胜平负，以及条件于本题集的配对区间；开发题数少、held-out 仅一家公司三题，不作跨行业显著性宣传。两个主对比独立呈现，不选择最有利指标作总冠军。若未来做显著性检验，需另行预注册公司级样本/多重比较，当前不承诺 p 值。

每批两遍全新 **gpt-6-astra/high**，`fork_turns=none`；只给匿名题面/完整答案/全部交付附件/原页参考/rubric。不提供组别、工具日志、运行失败原因提示或前一遍结论。第二遍反转顺序且重命名编号，链依赖仍留在同包。先封存两遍输出再解盲。正式 162 回合分 9 个至多 18 答卷的块、两遍共 18 个新评审线程；D2/D3 以 3 repeats 为一块维持依赖；六道扩展可按题对组成三个 18 答卷块，保持题别参考。新 held-out 与开发材料不混包。门槛 18 答卷两线程。线程数不是 provider 请求数。

沿用稳定性：实质缺陷有无逐案一致，适用维度平均绝对差≤0.5、最大差≤1。B 的历史严重性分歧用于在开跑前明确 rubric 示例（缺少应答 vs 错误断言、仍交付旧附件、基础设施失败），不能用新 held-out 调 prompt/判分。若未达标，原分歧保留；不得平均掉、取有利一遍或追加裁决直到过关。需要重评先声明原因和协议修订，旧结果可追溯。

## 冻结与失败处理

一次记录代码 commit/tree/工作区 diff、3001 PID/启动时间/健康、Pi/模型/provider/effort/系统提示和每工具 schema 摘要、实际三组能力开关、沙箱镜像/依赖；资料记录原 PDF/解析器、当前有效事实（含旧记录取代关系）、定义/指标别名/维度/期间/币种/单位/准则/口径、原页原表、研究预测截止日与可用性。保存题面、参考、选择器、rubric、执行次序与各自摘要。主线确认冻结窗口，项目会话空闲后记录快照；整个批次材料零写入，结束复核同一内容摘要。未提交附件表状态如实附列。

不新增模型轮次做常规核查；宿主日志/数据库只读摘要由程序完成。发现版本/配置/资料漂移、入库入口、隔离失效、取消后续发或快照不一致时立即停止后续队列并保留在途结果。取消信号在每个 POST 前统一检查，不能仅取消当前轮而继续发下题。上游传输中断/5xx 按已审规则留原回合并继续，不人工重发。F1.5 原生瞬时重试若进入 v3 冻结版，三组同策略、全部尝试留账。父题失败且没有可用交付，续题记 dependency_unavailable，不能由人补答案；所有预定位置留在计划表。
