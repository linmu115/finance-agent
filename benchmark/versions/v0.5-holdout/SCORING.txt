v0.5 评分协议（预测前确定）

匹配
以已登记文档、输入页和原 PDF 数值字形矩形定位，不能仅凭金额相等匹配。
单格来源矩形直接定位，可抓出金额写错；断行行名不要求挤在同一 source.text 中。
一个来源框涵盖多格时，必须借助唯一原始数值文字消除歧义；同值重复仍算定位不明。
模型不得用一条预测同时覆盖两个原格。每格多条结果中的多余条目计入预测分母；
如果同格还有矛盾结果，不能用一条正确结果掩盖矛盾，该格仍失败。

完全正确
数值精确到原文精度，原值、单位及倍率、币种、期间与起止日期、版本、合并口径、
金融概念和引用均通过。无需所有动态概念使用某个程序固定英文 ID；已公开稳定 ID
按合同核验，其余用预测前写定的概念条件。定义复核 metadata 可解释合法新定义。
比例的 currency=percent、normalized_unit=%；同比相对比例和百分点差值必须保留
不同的 unit_kind（ratio_percent / percentage_points）与金融含义，不能相互替代。
source.raw_value 可以保留“增加 X 个百分点”，评分器只解析该明确固定字面格式。

指标
precision = 完全正确格数 /（落入已计分表区的预测格数）。
recall = 完全正确格数 / 146 个明确 gold 格。
错误新增、额外重复、无法核验的表区来源进入 precision 分母。
遗漏和错误格进入 recall 分母。分别报告数值错误、概念/范围/期间错误、缺格、
错误新增、相同重复、矛盾重复、定位不明，以及每公司和每表结果。
统计门槛为 precision >= 95% 且 recall >= 95%；不把二者合成含义含混的 accuracy。
重大金额、倍率、币种、期间及披露范围错误另列；已知重大问题不能被总体均分遮盖。
统计过线也不等于流程、真实模型证据、重大问题验收同时通过。

模型审校证据
允许目录 canonical_alias 或真正经过 definition_review 的事实。
审校通过必须由宿主独立核验实际 Pi 原始请求/响应、来源指纹、原 owner、
原抽取 hash、定义修改前历史和同组引用原文；reviewed 字符串本身不是证据。
financial score 和 provenance/workflow gates 分开报告，不能混为一个正确率。

冻结规则
scripts/score_financial_tables_v05.mjs 独立于旧 scorer，不改写旧成绩。
先在虚构回归数据上验证评分器，再锁输入/gold/协议 SHA，READY 后只运行一次。
不得看预测后静默修改 gold 或评分器给旧正式成绩刷绿；若确有评分合同错误，
保留原报告并用明确的新版本、同一 run、零新模型调用单独解释复评。
