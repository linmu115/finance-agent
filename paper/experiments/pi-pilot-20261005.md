# 同模型通用 Pi 与金融项目的开发试跑

日期：2026-10-05。状态：六项任务已运行、原文抽查和产物评审完成，临时计算环境已关闭。

**本轮没有证明金融项目整体优于通用 Pi。** 两组预先冻结的核心数值样本均为 19/19；金融项目保存了可追踪的研究记录和三份结构化估值模型，估值口径也有具体改进，但完整入库显著增加了成本，观点入库、解释正确性、制图及附件交付仍有缺陷。这是一轮开发样本试跑，不是留出集实验，也不是总体准确率评测。

## 1. 实验问题与方法

比较同一个模型、同一个 Pi 内核，在通用文档/Python 工具和本项目金融工具、技能、结构化记录、核验与制图指导下的整体表现。两组使用 `deepseek-flash`、DeepSeek 官方兼容接口、Pi 1.0.0，全部在 3001 运行。主程序和金融实现的文件指纹从准备到结束未改变；试验中仅更新了方案文字和评审记录。

A 组使用现有宿主的 `generic` 评测配置，并非另装一个 Pi CLI；它保留相同的文档读取和沙箱条件，去掉金融工具、技能、数据和主题模块。共享工具说明仍提到了 A 组没有挂载的金融制图辅助模块，模型曾尝试导入后回退，这是本轮对照配置的一项瑕疵，已记录；因此不能把图表差异全部归因于金融专业能力。

| 条件 | A：通用 Pi | B：金融项目 |
|---|---|---|
| 起点 | 新项目、新会话、原始 PDF | 另一个新项目、新会话、相同 PDF |
| 能力 | 原文解析、页/表检索、隔离 Python、产物 | 同一底座，增加金融入库、专业技能、研究模型与来源检查 |
| 三项任务 | 财报分析、研报核对、现金流估值 | 逐字相同的问题 |
| 运行顺序 | A1、B1、B2、A2、A3、B3，串行 | 同左 |
| 推理 | 相同路由设置，实际 low/high 请求分别记录 | 同左；清洗主要 low，分析可 high |
| 计算环境 | 相同镜像；容器 2GB、2 CPU、无网络 | 同左 |

材料为瑞和数智 2025 中期报告（57 页）和国信证券 2025-07-16 伊利股份深度报告（38 页）。二者都曾用于开发，因此不能作为未知样本。PDF SHA256、任务文本摘要、评审标准摘要、实现指纹和调用计数见[机器可读结果](../../docs/evidence/pi-pilot-20261005/results.json)。完整问题与运行口径见[方案](../../design/pi-finance-comparison-protocol-20261005.md)。

评分文件在调用模型前冻结，只保存在评审侧，没有提供给模型。财报核心样本为收入、毛利率、经营利润、合并净利润和经营现金流两期共 10 格；研报核心样本为收入、归母净利润和 EPS 三个预测年度共 9 格。数值正确要求单位、期间、主体和实际/预测身份同时正确。另行检查金融逻辑、来源、图表和交付物，不用核心样本成绩掩盖这些问题。

每项配对任务采用相同的实验技术额度：1,000 次模型请求、5,000 万输入、200 万输出、5,200 万总 token、12 小时。所有任务均未触发额度。它们不是新增的正常会话限制，也不是人民币收费上限。

## 3. 原文与计算质量

### 3.1 财报与研报：核心取数正确，不等于解释正确

两组核心样本都为 19/19。这个分母只覆盖预先选定的主指标与预测，不覆盖所有附注、观点和回答句子。

| 任务 | 已验证能力 | 首轮发现的问题 |
|---|---|---|
| A1 财报 | 10/10；区分合并与归母，识别公允价值收益的重要影响 | 正文一处把税前亏损称为经营亏损；计算脚本在 CFO 调整中把应减的利息收入 29 加回，残差吸收了 58 的差额；正文与脚本不一致 |
| B1 财报 | 10/10；50/50 候选表有处理结论，519 条财务记录，4 项疑点 | 将董事借款余额减少列入经营性营运资本解释，原现金流表把相应收还款列为融资；部分来源页不支持结论；“全量入库”表述过满 |
| A2 研报 | 9/9；正确读取 DCF 中心 32.69 元，使用未舍入利润核对目标市值 | 脚本把少数股东损益符号颠倒，虽正文正确但核对 CSV 错；把跨年度减值数误读为资产类别拆分；回答过长 |
| B2 研报 | 9/9；机构、分析师、发布日期和预测身份登记正确 | 错读 DCF 基准格为 33.46/33.95 附近；将舍入精度导致的目标市值差额误判为报告瑕疵；正文观点没有形成结构化记录 |

B2 实际入库 **940 条数值记录、0 条结构化观点记录**，不是观点全部提取完成。38 页都有处理状态，其中 24 页 accepted、14 页 needs_review；两次观点写入因主体字段不正确失败后，模型提交空观点数组并把部分解释放入页备注。原文和备注保留，但“有处理状态”不能替代“语义内容已提取”。

### 3.2 估值：结构化工具有收益，但不能替代结果解释核验

评审没有要求两组估值相同，也没有以是否接近研报目标价判定正确。两组采用不同、明确列出的情景，应分别验证其公式和边界。

**A3**：独立复算企业价值 228,364.008 百万元，三种净债务情景每股 31.8508、35.8724、23.9965 元；35/35 敏感性格点与提交数据一致。但估值基准为 2024 年末，扣减项却使用 2025E 债务/现金而没有解释时间对齐；少数股东索取权和非经营性资产没有处理说明。价值图把“百万元除以 1,000”后的结果写成“千亿元”，标签尺度错 100 倍。

**B3**：保存三份带输入、公式、来源、版本和检查结果的模型，6/6 附件可下载。独立重算三份模型的 98 项算术检查全部一致，其中 53 项为敏感性格点。每股结果分别为 27.1913、28.4867、31.3627 元。模型使用 2024 年净债务和少数股东权益，说明账面代理与非经营性资产假设，并通过 g/ROIC 计算终值再投资；本轮 `terminal_use_is_assumption` 检查真实出现在工具结果中。这些是专业工具发挥作用的具体证据。

但 B3 的解释仍存在问题：

- 31.36 仍低于报告区间下限 31.51，不能说落入区间。
- 重建 FCFF 对原文三年的差额为 0.197、0.729、0.795 百万元，并非都小于 0.2。接近原表舍入数不能证明完全复现报告公式。
- B 相对 A 同时调整了资本开支和折旧摊销比例，不能把全部差额只归给资本开支。
- 报告与本次模型在对应敏感性格点的差额是 4.174–7.076 元，不是稳定的 4–5 元。
- 把其他流动资产视为现金只是一个明确的情景，不能由该情景接近目标价反推出报告真实采用了这种现金口径；估值时点、终值 ROIC 与过渡期路径也存在差异。

因此本轮支持“结构化模型使输入和计算更可核对”，尚不支持“金融项目整体分析更准确”的结论。

## 4. 图表、交付与运行可靠性

实际检查了 18 张最终图表，10 张出现中文方框；另有现金流桥图裁切、单位和并排坐标问题。B3 的两张图中文可读，但两侧热力图把 WACC 与 g 轴交换了，且色标各自归一化，不能按颜色深浅直接比较数值差。B1 虽加载主题，却在主题上下文之外作图并覆盖为容器中不存在的字体。脚本返回成功，不代表图片已经通过验收。

通用组生成的 CSV 和 Markdown 下载被服务拒绝。已定位 CSV 的共享宿主问题：Windows 把 `.csv` 识别为 `application/vnd.ms-excel`，而产物路由仅接受 `text/csv` 等有限类型。评审从本地只读复制文件完成核对，但这些副本不算模型成功交付。两组均没有把完整制图脚本作为附件交付；B3 的三份模型 JSON 是完整结构化计算产物，可与缺失的脚本交付分别评价。

B2 上下文达到约 839,944 token 时触发了一次 Pi 原生压缩周期，包含两次摘要模型请求，此后继续完成，没有人工追加指令。A3 服务中断后原任务恢复，也说明持久化恢复路径在本次事件中有效；退出原因仍未知，不能把这一事件写成内存泄漏已证实或稳定性已全部通过。

试验期间用户允许临时启用 Docker/WSL：WSL 总上限 4GB、2 CPU、无 swap，单计算容器 2GB；串行使用。Docker 启动遇到残留通信端点，保留运行目录备份后恢复；意外随 Docker 拉起的其他容器已停止。结束时活动计算容器为 0，Docker 正常退出超时后只终止经过路径核实的本次 Docker 进程，再关闭 WSL；原 `.wslconfig` 字节摘要恢复一致。最终没有 `vmmemWSL` 或 Docker 后台进程，只有本项目 3001 在监听，网页服务健康。

## 5. 如何解释成本差距

两组缓存都接近 97%，因此本轮高成本的主要现象是**金融工作流发送的内容和执行工作量更多**，不能继续只归因于缓存不命中。金融组已知未缓存输入约 210 万、缓存输入约 6,687 万、输出约 26 万；三者都会计费。

本实验的 B 组按当前默认流程完成全篇表格入库，而 A 组按问题选读。该差异是被测产品行为的一部分，但不是等工作量的纯模型消融。不能据此声称“金融能力本身导致约十倍成本”，也不能把 B3 使用已入库材料的成本与 A 的从零任务直接当成提效比例。后续应增加“统一预处理条件”和“入库后多问复用”的独立实验，计入首次入库并报告摊销。

还观察到 B1 从 low 转 high 附近有一次约 52.9 万输入未命中缓存，随后请求大部分重新命中；这只是相关事件，没有证实是强度切换直接导致。[提供商文档](https://api-docs.deepseek.com/guides/kv_cache/)也把缓存描述为基于前缀的尽力复用，并不保证固定命中率。

## 6. 后续迭代依据

以下是由本轮证据形成的缺陷清单，**不是已完成的修复，也没有改动 Pi 内核**：

1. 修复真实交付：文件类型采用明确的扩展名映射；模型与完整脚本可下载；制图必须反馈字体缺失、检查成图，而非只接受执行退出码。
2. 加强结果与解释的一致性：区间包含关系、残差上界、图表单位、情景改变了哪些变量，由程序输出精确结论；LLM 用简洁金融语言说明其影响。
3. 修复观点入库的主体契约与失败反馈，区分“页面已登记”“已阅读”“已有结构化观点”，不能以空数组获得过满的完成表述。
4. 修复异常中断用量核算：以请求和结算 ID 对账，未结算项保持未知，避免显示为零成本或零未知请求。
5. 在同样材料范围、同样预处理条件下增加配对实验；另测结构化数据在多轮研究中的复用收益。使用新材料和重复运行后，再讨论普遍优劣。
