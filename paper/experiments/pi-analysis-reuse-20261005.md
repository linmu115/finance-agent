# 复用已入库资料的三组金融分析对照

日期：2026-10-05。性质：开发回归实验，非未见样本测试，非统计显著性实验。

## 研究问题与控制条件

本轮将完整入库作为已经完成的资料准备工作，不重复上传、清洗或修改来源数据，也不把历史入库费用计入分析成本。冻结资料为 57 页瑞和数智 2025 中报、38 页国信证券伊利深度报告；数据库包含 612 条财务事实、998 条研报数值、78 条观点，99 条待核验研究记录保留。财务事实和研究记录的联合 SHA-256 为 `bb4360c934ec07e9d30bd47d29ade61437d7b43698ab4f99b2509e32628f4357`。

| 组别 | 能力 | 分析起点 |
| --- | --- | --- |
| A 通用 Pi | 原文、原始表、检索、Python | 两份相同 PDF 的已解析原文 |
| B 通用 Pi＋整理数据 | A 的能力，加结构化记录查询 | 与 C 相同版本的财务、研报记录 |
| C 金融 Agent | 当前金融工具、技能、模型复用、制图助手 | 与 B 相同的数据 |

字体、沙箱、完整脚本导出和 Pi 主循环是三组共有能力。所有任务在同一项目的独立新会话发起，禁止读取其他会话的答案和旧模型；模型更新题只承接该组本轮自己新建的模型。问题在发送前冻结，答案标准不放进模型工作区。普通产品的完整入库行为没有改变。

四道问题依次覆盖利润与现金流、机构预测和 PE、三年 FCFF 折现、同模型的三项局部更新。最终答案、CSV、图表、真实下载、完整脚本和沙箱复算分别验收；不能用核心数值正确率代替整体分析正确性。

## 运行中的实际干预

第一轮暴露出沙箱未将 stdout/stderr 返回给模型的问题，导致模型看不到具体脚本错误而重复修改。该轮保留，不混入修复后的成绩：已知费用约 ¥1.0602–2.1203，另有一笔取消请求的用量未知。修复仅将既有日志反馈给调用方，同时让原文准备工具复用已入库文档已有的原文，不重新解析或清洗。针对性回归 23 项通过、2 项跳过，真实容器验证返回具体异常后，在新会话重跑。

修复后 DeepSeek Flash 完成三组首题，随后返回 HTTP 402。失败记录保留；剩余三题使用此前获用户授权的本机 CPA `gpt-6-luna`，重新建立三组匹配会话。两个模型的结果分别呈现，不混合金额或据此比较模型优劣。CPA 的路由请求返回错误，其用量记录为未知；主分析按应用已有规则采用 high，具体请求记录保留。

试验期间没有给予任何一组人工金融纠错或提示其调用某个特定工具。遇到的答案和图表错误保留为失败项，不为了比较结果而修正。

## DeepSeek Flash：财务分析首题

单位：输入、输出为已返回的累计 tokens；金额按 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)的空闲至高峰单价区间估算，不是账单。思考 tokens 已包含在输出内，不重复计费。

| 指标 | A 通用 Pi | B 通用 Pi＋整理数据 | C 金融 Agent |
| --- | ---: | ---: | ---: |
| 请求数（含路由） | 22 | 26 | 36 |
| 核心数值样本 | 10/10 | 10/10 | 10/10 |
| 累计输入 | 1,370,550 | 2,177,475 | 8,226,486 |
| 累计输出 | 39,593 | 46,672 | 65,296 |
| 已知分析费（元） | 0.264–0.527 | 0.320–0.640 | 0.678–1.355 |
| 交付文件实际下载 | 20/20 | 21/21 | 20/20 |

核心样本是收入、毛利率、经营利润、合并净利润、经营现金流五项指标的两期数值。三组都区分了 63,015 千元非现金公允价值收益和经营结果，披露了利润到现金流调节中的未解释差额。然而三组都没有通过完整质量验收：

- A 的最终瀑布图纵轴为千元量级，却标为百万元；结论将绝对现金流与现金流率的变化混用。
- B 的最终瀑布图存在标签重叠及负向柱裁切；“现金端未改善”没有区分绝对净流出已经收窄与收入现金转化率恶化。
- C 的 CSV 和核心数值表正确，但四张图将千元换为百万元时多除以一千，导致多个数据标签变成 0.0；文字把以权益为分母的杠杆率误称为资产负债率，并称毛利为“唯一下拉项”，与同一底稿中的其他负贡献不符。

C 的已知分析费为 A 的约 2.57 倍、B 的约 2.12 倍，本题没有形成整体质量优势。其两次财务查询返回约 57.7 万字符，三次目录调用返回约 20 万字符，又执行了七个分析脚本。缓存命中率高并没有消除反复携带这些内容及输出脚本的费用。这里的字符数来自序列化工具结果，不能等同于模型 token 数，也不能单凭它精确分摊费用。

最终业务文件的脚本已在原沙箱输入下复算。A 六个文件、B 七个文件字节一致；C 的计算数据、CSV、报告及 PNG 一致，四份 PDF 仅创建时间元数据不同，渲染像素和提取文本一致。复现了错误图表也仍然是错误，复算成功不代表金融正确。

## GPT-6 Luna：研报、建模和复用

研报题三组均完成。三年收入、归母净利润和 EPS 共九个样本值均为 9/9，机构署名、预测身份、PE 乘法和主要风险说明通过；不能据此认为三组交付均无问题。

| --- | ---: | ---: | ---: |
| 已知输入 tokens | 171,093 | 385,871 | 688,463 |
| 已知输出 tokens | 5,711 | 7,654 | 6,536 |
| 未知用量请求 | 1 | 1 | 1 |
| 附件卡片下载 | 5/5 | 8/8 | 6/6 |
| 最终图表核验 | 中文字形缺失 | 通过 | 通过 |

A 的脚本覆盖了共享中文字体配置，使用容器中不存在的字体，中文变成方框。B 在收到真实字体警告后自行修正，C 使用金融主题一次生成两张可读图表。B、C 的图表在本题具备可见交付优势，但 C 的输入仍然更高，不能据此宣称金融分析整体优越。

三组回复正文中的下载链接均存在问题：A 使用 Windows 相对路径，B 使用被渲染器清空的 `sandbox:` 路径，C 使用返回应用 HTML 页面的相对路径。附件卡片的真实 API 下载全部成功。已分别记录“底层下载成功”和“正文链接失败”，不以其一掩盖另一项。最终业务脚本均在同一沙箱成功复算。

三组 DCF 初建和局部更新均已结束，未给予人工金融纠错。每组初建的三年 FCFF、EV、股权价值、每股价值及九点敏感性共 15 项数学复算均通过；每组更新的 FCFF、估值、顺序归因及两版敏感性共 34 项复算均通过。三组都只改了指定参数，也都没有在更新题重新读取整篇财报。这些是数学一致性检查，不是总体金融准确率。

货币费用未知：CPA 没有已核实的计费单价。日志中的 Pi 模型目录估价不等于 CPA 账单，因此不将其作为本表费用。每题各有一笔路由请求没有用量，已知数不能冒充完整账单。

本次全部 DeepSeek 请求（包括首次诊断、正式首题以及后续余额不足的尝试）的已知累计输入为 19,107,705 tokens、输出为 303,117 tokens，估算 ¥2.3450–4.6900，另有 12 笔请求用量未知。这里的全部支出用于透明记账，不拿来计算三组的有效任务成本倍数。CPA 三题的九次路由未知用量另记，不与上述 12 笔相加后冒充某一提供商账单。

初建时 A/B 使用末年 FCFF 增长外推终值，每股价值为 30.5211 元；C 使用稳定期 NOPAT 与再投资率 `g/ROIC` 推算终值，明确假设稳定期 ROIC 为 10%，每股价值为 22.9985 元。两者均按各自披露的方法核验，不能以接近报告目标价为正确标准。局部更新后分别为 27.1932 元和 20.7692 元，所有组均保持原有终值方法、估值锚点、股数及未指定修改的输入不变。

C 实际复用了本轮自己的模型 ID，并调用版本比较工具。工具返回的七个字段变化（WACC 及三年 Capex、D&A）、每年 FCFF 和顺序归因通过独立复算；保存了新旧版本及来源关系。C 对债务表口径冲突、稳定期再投资和少数股东权益代理的解释更完整，这是本题可观察的专业增量；A/B 也正确完成了计算与局部更新，因而不能据此宣称 C 独有该能力。C 的输入中仍把 2024 历史收入标成机构预测，属于需要修正的来源身份错误。

其余交付问题没有被数学通过掩盖：

- A/B 在初建答复中给出的部分单元格定位错误，例如将收入指向现金行、将 EBIT Margin 指向权益融资行；实际计算值正确。C 使用的页码来源可定位，但其部分来源身份字段仍有上述错误。
- A 更新题的两幅敏感性图共用正确的绝对网格与色标，但总标题和面板标题重叠。
- B 更新题的瀑布图将负变动柱的起点多减了一次，柱位置与归因数值不符；例如 WACC 的负变动应连接 30.5211 与 27.7774，实际柱体落在 27.7774 至 25.0337。归因 CSV 正确。两幅敏感性图色标一致，但深色单元格标签对比度不足。
- C 更新题的并列图数据、坐标和色标正确，深色标签仍不够清晰；最终回复“WACC 和终值等既有口径未变”容易与已明确变更的 WACC 数值混淆，应将参数值和估值方法分开表达。

C 初建导出用了六次脚本：一次公共布局冲突、四次相同的语法错误、最后成功。C 更新又因导出末尾的变量名错误修复一次。A/B 初建各有三次脚本调用，更新各一次。所有失败及自主修复用量均纳入上表，没有删掉不利样本。数学工具已经给出结果后，C 仍重新编写计算和导出代码，形成重复输出与修复开销；“有专用工具”尚未自动转化为较低成本。

两模型下共 12 项任务结束，142 个返回的附件卡片文件（含中间版本）全部实际下载成功。每项最终业务产物的生成脚本均在原输入和原隔离沙箱内重放；CPA 部分全部字节一致。独立数学检查、导出数据一致性与人工图表检查分开记录。原始资料、会话、请求记录及脚本位于本地 `data/evaluation/pi-analysis-20261005-r2/` 与 `data/evaluation/pi-analysis-20261005-cpa/`；可分发结果见 [DeepSeek 汇总](../../docs/evidence/pi-analysis-20261005/deepseek-results.json)、[CPA 汇总](../../docs/evidence/pi-analysis-20261005/cpa-results.json)。

## 结果解释与工程收尾

本轮排除了新增入库成本，金融组仍没有表现出整体成本或准确率优势。GPT 三题累计输入为 A 的约 2.87 倍，累计输出为 A 的约 2.41 倍；DeepSeek 首题已知分析费为 A 的约 2.57 倍。缓存命中并非主要缺失：大量结果被带入多轮上下文，以及重复写计算和图表脚本，仍会产生费用。准备好的数据也没有在 B 组自动降低输入；仅增加结构化记录入口不足以证明整理数据的收益。

结果支持继续改进金融数据到计算、计算到交付的直接复用，而不是削减完整入库或改造 Pi 主循环。优先目标是让查询只返回任务所需的准确记录与可按需展开的来源，让制图/报告脚本直接读取已保存的模型结果，减少重新推导和输出同一套计算。单位、坐标及来源身份应由已绑定的数据带到图表，不能依靠模型再手写一遍。该方向是本轮证据支持的后续工作，尚未获得新一轮效果验证。

正式对照结束前，两轮的运行代码哈希、财务和研报记录哈希均未改变。随后单独完成两项收尾，不回写原始成绩、不再次调用模型：

1. 移除公共绘图环境强制启用的布局引擎，让脚本自己选择 `tight_layout` 或 `constrained_layout`。三份原始失败脚本在相同输入下重放，布局冲突全部消失；A/C 脚本直接完成，B 继续暴露其本身的浮点值检索错误。因此这是公共环境修复，不是将三份脚本都评为成功。见 [重放记录](../../docs/evidence/pi-analysis-20261005/post-trial-layout-replay.json)。
2. 将回复中指向已附加文件的相对路径、Windows 路径和 `sandbox:` 路径映射到真实附件下载地址。仅匹配本条回复的已知附件，保留项目权限及 Markdown 链接安全过滤。50 个实际回复链接经过 React Markdown 渲染及 HTTP 下载均成功。见 [链接检查](../../docs/evidence/pi-analysis-20261005/post-trial-link-check.json)。三项相关回归、类型检查和前端构建通过。原有回复和实验文件未被修改。

服务仍统一在 3001。实验后停止临时 Docker/WSL，恢复原 `.wslconfig`；最终环境读回见 [收尾记录](../../docs/evidence/pi-analysis-20261005/environment-cleanup.json)。

## 解释边界

两份材料曾用于开发，所有结论仅对当前版本和这组问题成立。每个组合只运行一次，缓存热度、实际推理输出和模型选择的工具路径并未固定。费用包括模型自己发生的失败和修复；资料准备支出单列。DeepSeek 耗尽余额后的失败请求及 CPA 路由请求未知用量不记为零，CPA 本机代理没有已核实的货币费率，不沿用模型目录估价充当真实费用。

实验保留在论文补充中；已发布 v0.2.0 正文及 PDF 不被悄悄覆盖。原始对话、模型私有推理、凭据和主数据库不进入可分发证据目录。
