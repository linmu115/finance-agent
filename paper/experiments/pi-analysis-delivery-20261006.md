# 查询压缩、模型复用与交付一致性：开发对照（2026-10-06）

本文记录在既有资料上进行的分析测试。入库功能保留，本轮新增入库调用为零。原始实验与随后修复的配对复测分开报告，不覆盖失败答案、不以修正后的产物替换首次成绩。

## 实验条件与可解释范围

主实验使用同一个 CPA `gpt-6-luna`，比较 A（通用 Pi＋原文与 Python）、B（通用 Pi＋相同结构化记录）、C（金融工具与技能）。四项问题依次覆盖利润与现金流、研报预测与 PE、DCF 初建、同会话局部更新；完整原题沿用上一轮分析协议。各组有相同的中文绘图环境、原脚本交付及局部修改能力。运行顺序事先固定，过程中不发送金融答案或纠错提示。

资料为 57 页睿和数智中报与 38 页国信证券伊利研报。612 条财务事实、998 条研报数值和 78 条观点的测试前后内容摘要一致，99 条待核验记录保留。运行代码的 99 个文件摘要在主实验前后完全一致。主实验 12 项运行均结束，但“结束”不代表金融及交付质量全部合格。

这是一轮使用已见材料的开发回归，每种任务每组一次。缓存热度未控制，路由策略一致但模型实际推理强度可能随请求不同。不能据此声称统计显著性或对新材料的泛化优势。CPA 没有核实的货币费率，以下只报告上游已返回的 token；每项另有一次未返回完整用量的请求，未知不计作零。

## 本次实现

1. 模型查询结果去除重复处理历史和审计正文，保留数值、原值、单位、期间、口径、疑点、版本与来源定位。完整数据仍在数据库与原文接口中；不按工具次数或证据年龄丢弃内容。目录支持按资料或公司筛选。
2. 记录 ID 可直接绑定计算输入，程序按规范金额、模型金额单位、股数单位换算，并保存来源与实际／预测身份。模型仍负责口径和方法选择。
3. 分析显式选择已保存的模型版本，直接读取结果；自动交付输入、结果 CSV 和包含原计算器的复算包。小修改可以复用上次脚本，避免重新实现计算。
4. 提供标准 Matplotlib 辅助函数，将金额值与轴单位一起换算，处理带负数的瀑布图、敏感性图坐标和色标。图形、排版和解释仍由模型按问题编写。

对上一轮 127 条财务记录的两次真实查询离线重放，模型侧内容从 425,188 字符降到 149,574 字符，减少 64.82%；逐项比对数值、单位、口径、疑点与原格定位保持一致。这是固定查询内容的缩减，不等同于端到端输入 token 或费用下降。

## 主实验：尚未形成整体优势

| 任务 | A 输入／输出 | B 输入／输出 | C 输入／输出 |
|---|---:|---:|---:|
| 利润与现金流 | 172,767／6,082 | 527,633／8,508 | 599,742／8,092 |
| 研报与 PE | 127,449／5,025 | 378,435／7,420 | 215,129／5,451 |
| DCF 初建 | 272,228／5,025 | 2,365,653／11,246 | 2,242,126／19,450 |
| DCF 更新 | 228,017／5,080 | 1,571,607／8,786 | 1,012,991／6,936 |
| 合计 | 800,461／21,212 | 4,843,328／35,960 | 4,069,988／39,929 |

C 的累计输入约为 A 的 5.08 倍，输出约为 1.88 倍。高缓存命中不能抵消额外取数、长历史与返工造成的累计输入。B 的部分返工还受到公共工具说明错误的影响：说明声称可用金融绘图辅助库，但通用环境没有挂载它。此缺陷随后修复，不能把这部分人为成本当作金融系统优势。

### 金融质量和实际交付

| 任务 | 样本核对 | 主要发现 |
|---|---|---|
| 利润与现金流 | 三组所问核心数值均 10/10 | C 的非现金、财务费用与税费分类更完整，残差明确；A 中文图有缺字，B 报告费用变动单位有十倍错误。C 仍经过两次脚本修补。 |
| 研报与 PE | 三组九个预测值均 9/9，预测身份与 PE 复算正确 | A 交付较好；B 图中文字和布局有缺陷；C 将百万元除以 1,000 后标成亿元，金额图少显示十倍。 |
| DCF 初建 | A/B 来源与运算检查 30/30；C 的十五项来源输入仅 4/15 | 第 36 页已有 D&A、资本开支、营运资金、债务现金和少数股东权益；C 没有读到，使用了可避免的假设。其自有假设下独立运算 15/15 正确，仍不能认定任务完成。 |
| DCF 局部更新 | 三组均正确更新各自原模型并保持绝对敏感性网格 | C 用一次沙箱执行复用模型和顺序归因，避免了重写 DCF；但其原模型缺失仍继承，导出报告出现十倍金额单位错误、基准 FCFF 列误写为更新值，三组并列图均有色标遮挡。 |

上述核对项不同，不能把各题通过项相加解释为总体准确率。尤其需要区分来源完整、公式运算、文字解释、图像与可复算交付。C 的初建脚本反复修补，其中六次修改在执行前因文本匹配问题失败、五次沙箱运行失败；另写的复算脚本仍存在语法错误。实际执行脚本与自动交付的原计算器包可用，两者不能混为“所有脚本可用”。

DCF 终值方法也影响数值：A/B 采用最后预测年 FCFF 延伸，金融工具采用稳定期 ROIC 再投资法。方法被明确说明时，价格不同本身不判错；遗漏已经提供的来源数据、隐瞒外推假设或错误单位才构成实质问题。局部更新按照同一模型基准核对，不用目标价接近程度评分。

## 主实验之后的针对性修复

原始记录封存后，修复以下实际接口问题：

- 研报多个检索词按任一词匹配，并识别 FCFF、D&A、CAPEX、NWC 等常见中英文字段别名；同一资料和项目权限筛选仍生效。原来没有命中的四词检索可返回相应记录，数据本身没有改写。
- 修正通用／金融环境各自的工具说明与可用中文字体，避免基线被错误说明拖累。
- 脚本修改错误明确返回匹配数量，提供显式批量替换；无变化修改直接返回原因，不再执行同一份错误脚本。没有增加模型审批或检查关卡。
- 金额绘图一步绑定数据缩放与单位；修正技能中过时的单位说明，以及新模型 ID、已有计算器交付的指引。
- 已保存模型的精简回执重复进入历史时，保持“输入已保存”标志，不再错误变为未保存。

配对复测在启动前登记为 A2、C2、C3、A3、A4、C4，使用完全相同的原题、资料和模型。没有向模型提供第 36 页或具体数值提示。复测只用于判断修复后的变化；开发者已经看过失败材料，不能当作新的盲测。

## 配对复测：模型复用改善，总体优势仍未成立

六项运行均完成，运行期间 99 个文件摘要一致，入库资料和目录内容仍未改变。下表是相同原题的新一轮 A/C 配对结果，不拿金融组的新成绩与通用组旧成绩混比。

| 任务 | A 通用 Pi 输入／输出 | C 金融项目输入／输出 | 结果 |
|---|---:|---:|---|
| 研报与 PE | 166,869／8,023 | 417,076／7,636 | A 九项预测底稿值正确，图中目标价标签重叠；C 正文九项正确，但 CSV 的六个金额值大十倍，图中的金额小十倍。 |
| DCF 初建 | 260,933／6,693 | 923,162／16,581 | 两组均取到所需来源数据并正确运算；C 来源输入样本从首轮 4/15 改善为 15/15，独立公式核对 15/15。两组终值方法不同且已明示。 |
| DCF 局部更新 | 655,639／11,835 | 827,532／6,297 | 两组正确保持非目标输入、修改三个参数组、归因并保持绝对敏感性网格。C 直接复用版本与比较，报告、底稿与模型数值一致。 |
| 合计 | **1,083,441／26,551** | **2,167,770／30,514** | C 输入约为 A 的 **2.00 倍**，输出约为 **1.15 倍**。 |

两组已知输入的加权缓存命中率分别为 88.61% 和 90.25%。每组另有三笔请求的完整用量未知；CPA 货币费率未核实，不能把这些 token 比例直接叫作费用比例。模型请求日志显示，本轮主分析均为 high、路由为 low，没有用不同的推理强度人为给某组加分。

可以确认的局部收益是 DCF 更新：C 一次分析脚本成功，A 三次中一次因缺少可选排版依赖失败；C 输出减少 46.79%，任务用时从 A 的 254.8 秒降到 180.3 秒，减少 29.25%。C 初建、更新均直接读取保存版本，没有重复编写 DCF 计算器。复测的两个原计算器包包含三个模型版本，均在独立沙箱用随包原计算器复算一致。这是单个开发案例的复用收益，不代表广泛或统计显著的优势。

C 初建相对自己的首轮失败运行，已知输入减少 58.83%，且不再遗漏已有的 D&A、资本开支、营运资金、现金债务及少数股东权益。但在同轮配对中，C 初建输入仍是 A 的 3.54 倍，存在两次来源参数错误和三次不支持的运算调用。C4 延续前题上下文，更新首个主请求的记录内容约 35.0 万字符，A4 约 18.5 万字符；即使本题工具次数更少，携带的历史仍较长。该字符统计用于解释输入负担，不等于提供商计费 token，也不构成另加上下文截断策略的理由。

最关键的未通过项是**金额展示一致性**。C2 没有使用现有单位辅助函数，而是在脚本中重新转写金额：原来源单位是百万元，正文正确；图形按十亿元数值画图却标为亿元，CSV 又采用了另一套错误缩放。提供正确工具不等于模型稳定使用它，本轮不能宣称单位错误已消除。两组敏感性图还存在深色单元格文字对比不足等细节；C4 额外交付的一份带“两版”名称的 CSV 实际只含基准版，完整两版输入和结果另有独立文件提供，亦保留为交付缺陷。

因此，本轮实现完成了查询精简与模型结果交付，真实测试证明了局部复用收益，**尚未证明金融 Agent 在整体质量或总开销上优于通用 Pi**。下一步的主要缺口是让答案、底稿和图形使用同一份带单位的计算结果，以及减少金融工具参数猜测和返工；不是增加逐步模型复核。这个结论保留负面样本，不靠删除失败运行或更换评测口径改写成绩。

## 对照结束后的附件下载修复

A3/A4 合计 15 个文件已实际生成，但保存在输出子目录时，服务下载路由只接受单层文件名，返回 HTTP 400；A4 正文另有一个写短的运行 ID。这是两组共用的应用交付缺陷，不能当作金融专业能力的优势。

在六项复测及运行代码摘要封存之后，修复下载路由和正文路径映射，保留原来的项目归属、文件清单、路径与摘要校验。对子目录文件用完整相对名称匹配；对无效运行 ID，只解析当前回复中名称唯一且完全一致的已附文件，有效的其他运行 ID 不自动替换。

没有再次调用模型或替换文件：原来失败的 15 个下载全部变为 HTTP 200，文件摘要与沙箱原产物一致；复测实际回复经 Markdown 渲染后，42 个文件链接全部解析和下载成功。跨项目及目录穿越请求继续被拒绝。初次 HTTP 400、正文错误和金融质量缺陷保留在原始评分中，修复后的下载另存证据。

## 验证与环境收尾

实现阶段 Node 174 项、Python 428 项、类型检查和构建通过。复测修复另有 18 项 Node、35 项 Python 专项核对；其中一个测试夹具在 Windows 清理 SQLite 时未关闭连接，修正夹具后该项通过。下载修复的 4 项 Node 与 11 项沙箱宿主规则测试通过，2 项符号链接测试因本机不允许创建链接而跳过，类型检查和生产构建通过。

两轮 18 份最终实际执行脚本均在隔离沙箱重新执行成功，182 个生成文件摘要全部一致；四个金融模型包的六个模型版本复算一致。可重复生成不等于内容正确，C2 的错误图和错误 CSV 也会被原脚本准确重现，已单独判错。

临时 Docker Desktop 与 WSL 已关闭，没有残留的 Docker 后端、vmmemWSL 或运行中的 WSL 发行版；原 `.wslconfig` 按字节恢复。3001 已加载最终下载修复并健康运行，3002/3003 无监听。没有改写原始入库数据、删除旧实验或启动新的模型任务。
