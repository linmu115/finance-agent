# 统一数值交付与新公司对照

状态：15项分析对照及逐项复核已完成。运行结束不等于交付全部正确；本轮仍未证明金融组整体质量优于同数据通用Pi。正式分析运行代码与准备数据前后摘要一致，新增入库为零。

## 问题与改动

前一轮同模型实验中，金融组正文数值正确，但自主编写交付脚本时再次换算单位，导致图表小十倍、CSV 大十倍。只在提示词提醒单位或提供可选换算函数，并未保证真实交付一致。另一方面，已有数据库记录和金融模型结果被重新抄写进脚本，产生额外输出与返工。

本轮为现有分析工具增加数值报告对象。输入可引用事实、研报记录或不可变模型版本，程序将原数值转换到展示单位一次，转换后的同一组数据生成 CSV、标准图形和报告占位符。自由计算及自定义图形仍可由模型编写 Python；导出的精确数据及渲染脚本可以复算。金融模型输入同时接受记录引用，复用原有来源绑定，不增加额外模型核验轮次。

这一机制约束的是采用该交付路径的数值，不能保证任意手写脚本、自由正文或错误口径自动正确。因此，需要观察模型是否实际采用工具、源记录本身是否正确，以及最终答案是否准确。程序测试通过仅证明测试条件中的行为。

## 材料和实验设计

新材料为卡罗特 2025 中期报告（55 页）及招银国际 2024 年 11 月 8 日卡罗特首次覆盖报告（47 页）。两份材料未参与此前的伊利、瑞和回归，原发布者链接及文件摘要见 [实施方案](../../design/finance-generalization-20261006.md)。实施者事先读原文制定独立评分依据；评分文件不进入项目、不挂载给 agent。

三个条件均使用本机 CPA 的 GPT-6 Luna 和相同推理路由政策：A 为原文与 Python 的通用 Pi；B 为同一份准备数据与 Python 的通用 Pi；C 为金融工具及技能。三组共享基础图表、字体及数值交付功能。B/C 为主比较，各重复两次；A 为辅助比较，每题一次。共三类题目、十五次任务，顺序事先确定。每个重复使用独立会话，局部更新仅沿用自身初建会话。

任务分别考查中报利润与经营现金流解释、研报预测与 PE/DCF 复算、DCF 的局部更新及顺序归因。报告内净利润、EBITDA、风险溢价等不一致应有来源地保留，不能为了接近目标价篡改输入。机构预测、来源事实和分析假设分开表达。

入库作为一次性准备支出单列，后续十五次分析禁止重新入库。冻结前后的结构化记录与运行代码均记录摘要；评估时保留失败尝试、未知用量及人工干预。真实 CPA 费率未经核实，目录估算不视为账单。

## 准备阶段验证和故障

真实 Docker 沙箱的合成金额测试通过：图表柱高、轴单位、CSV 和报告一致，负值、预测标识及中文图形可用，可重新渲染包的数值输出一致。该验证未使用待评估公司数据。

首次财报准备暴露出宿主 JSON 参数适配错误：应用向 Responses 接口添加了 Chat Completions 的 `response_format`，清洗请求返回 HTTP 400。主动停止后保留请求日志、失败批次和未知用量，按 Pi 模型目录的 API 类型修正为对应参数。当前模型的真实最小 JSON 请求成功，再在原会话继续准备。该修复在正式分析冻结前完成，后续三组使用同一版本；不改变 Pi 内核、模型选择或入库范围。

另一处既有参数分支把任何非空 review_metrics 都当作旧抽取入口，即使 review_existing_only=false 也如此，导致原本要求的脚本清洗和来源分类被绕过。已将分支改为只有显式复核已有指标才进入复核；普通入库走原有脚本准备流程。两份材料的早期尝试停止并保留，正常清洗提交会保存旧解释历史。这里修的是工具语义与执行路径不一致，而不是追加模型检查步骤。

进一步发现空可选 reviews 列表被当作零张提交，返回成功却没有写入映射；改为与省略该字段一致，正常提交所选表，且不宣称额外语义核验。23 项清洗回归通过。准备模型仍多次提前结束未完成任务，出现将未读数值表直接排除的候选脚本、资料 ID 混淆等问题。人工续接、指明具体参数错误和全部原始尝试都保留在 setup.json；会话正常结束不等于资料完整入库。

用户随后批准仅资料准备使用GPT-6.1 Sol，分析各组仍统一GPT-6 Luna。准备模型改变单列记录，不混入分析优势比较。两种模型经同一本机CPA及Pi原生Responses路径执行相同合成JSON/工具链，共8次请求均收到HTTP 200和response.completed，取数、单位换算、提交成功。现存代理错误日志对应早期400，旧末次任务未出现输出截断；这些证据不足以排除长任务中的偶发代理故障，也不能证明上游实际模型身份。后续真实请求增加状态码和流结束元数据审计，未增加模型步骤。

独立检查发现财报59张已提交表中36张零数值，部分涉及主表续表和财务费用附注，不能视为完整入库或据此冻结公平对照。旧脚本曾对映射失败直接给出排除理由；这些候选和历史保留，后续准备需据原文修正，不能用覆盖计数代替内容验收。Docker重启又遇到Secrets Engine旧通信文件，删除被自动审批拒绝；已退出Docker并请用户手动处理。等待期间，Sol先处理不依赖沙箱的研报正文。

## 验收与结论边界

正式分析的B1任务发生宿主中断：Node在追加审计文件时收到Windows `EBUSY`，未处理的错误导致3001退出。保留原服务错误日志和恢复前审计，使用同一冻结代码重启后，Pi沿用保存的会话继续并完成；没有新增金融纠错提示。该任务有1笔用量未知，恢复等待计入运行用时。尚不能确定文件临时占用的来源。这一事件属于宿主可靠性问题，不能归因为模型能力，也不能从实验中删去。

恢复沙箱后，准备阶段还发现英文报表单位解析缺陷：`RMB’000`只识别币种而遗漏倍率，导致规范记录错误地等于原始千元数值。程序已支持多币种的英文数量级写法，脚本提交回归及旧跨页识别通过；通过正常清洗更新受影响记录，保留原版本。这一发现说明输出端一次换算只能保证既定输入的一致交付，不能替代来源单位及记录语义的正确性。修复发生在正式分析冻结前，不将这轮人工修复记为模型自主表现。

逐题记录关键金额和金融口径、来源身份、计算复算、图表/CSV/正文一致性、附件下载，以及输入/输出、调用次数、重复脚本和用时。金额趋势相同不能弥补绝对金额错误；服务完成状态不能代替财务正确性。

本轮是单一新公司的小规模筛查。即使某题结果改善，也不推导跨行业泛化或统计显著优势。此前负面实验成绩保留。下列为全部预定任务的结果，不挑选最好的一次。

## 正式分析结果

主比较为同一份准备数据上的通用Pi（B、D）与金融项目（C、E），各三题、两次重复。A是同一原文的通用Pi辅助组，只运行一次，不与六题总量直接相除。模型请求均登记为CPA GPT-6 Luna，路由为low、主分析为high；无法独立验证代理背后的实际模型身份。

| 已知用量/过程 | 同数据通用Pi，6项 | 金融项目，6项 |
|---|---:|---:|
| 输入token（包含缓存读取） | 5,123,875 | 2,674,311 |
| 其中未命中缓存输入 | 369,443 | 423,047 |
| 输出token | 53,264 | 40,874 |
| 缓存读取token | 4,754,432 | 2,251,264 |
| 加权缓存命中率 | 92.79% | 84.18% |
| 登记模型调用（含用量未知） | 83 | 56 |
| 其中用量未知的请求 | 1 | 0 |
| 沙箱执行失败次数 | 12 | 2 |

金融组累计输入少47.81%，输出少23.26%，但未缓存输入多14.51%。因此不能据总输入减少宣称实际费用同比下降，更不能以高缓存命中率代替质量评价。CPA费率未核实，不给出伪精确的货币账单。上述准备费用完全排除；B1中断未结算的一笔用量保留未知。

按题观察更能说明边界：利润/现金流题的金融组输入反而多35.48%，输出少49.15%；研报估值题输入少71.89%、输出少12.28%；局部更新题输入少9.39%，输出却多5.68%。前两题通用组的一部分额外开销来自共有报告接口拒绝自然单位写法后的多次修补，不足以证明金融推理本身更高效。

| 任务 | 同数据通用Pi | 金融项目 |
|---|---|---|
| 利润与现金流 | 主表金额及现金流桥正确；D1导出报告开头将收到利息写成扣除，与后面的正确计算矛盾。B1有小幅同比舍入表达差异 | 主表金额及桥接正确；结合管理层解释区分关税、费用和利息影响，E1还正确区分了投资现金流中的定期存款利息。这是局部解释质量收益，不是独立专家评分 |
| 预测与PE/DCF | 核心预测与DCF计算正确；B2较完整指出EBITDA/风险溢价等来源矛盾。D2参数CSV把0.122/0.02标为%，图上WACC刻度还被取整 | 核心DCF计算正确；C2的净利润CSV仍保留百万元数值却标亿元，错100倍。E2修正了这类金额交付，但其参数CSV同样把小数比例标为%。C2仅反推PE隐含汇率，独立复算不完整 |
| 局部更新 | 新旧估值、两项贡献、18格敏感性计算正确；D3继承参数CSV的百分比单位错误，图形仍有深色单元格对比度问题 | 相同计算均正确，但E3也继承参数CSV单位错误；C3标题重叠，E3色标覆盖右图内容。没有体现稳定的交付质量优势 |

各组独立DCF均得到约HK$10.891298/股；按指定顺序调整后约HK$9.407640/股，两项贡献分别约-HK$0.506914和-HK$0.976745。原文A组也能完成这些核心计算，所以不能把正确算出DCF本身当作专业系统独有贡献。A组的图形同样存在色标重叠、可读性等问题。

两次金融更新都未调用保存模型的版本更新接口，仍重写计算与导出脚本；E3虽成功读取已保存研究底稿，也不等于复用了原计算器。五次更新均没有重新读取整份PDF，但金融两次更新的代码字符总量比同数据通用组多19.27%。本轮没有证明模型复用机制已在真实行为中稳定兑现。

## 交付与实现缺陷

全部156个登记产物均能下载。18次成功的沙箱执行在相同镜像和原始输入包下重放；155项文件内容检查一致，其中ZIP按解包后条目内容比较，避免把创建时间差异视为数值变化。另一个产物是保存的研究报告JSON，通过实际下载核对，不属于脚本重放。复现原错误不等于正确性通过。

本轮明确暴露了四类通用问题，原结果不回写：

1. 数值报告路径只约束采用该路径的数据；模型自行导出CSV时，金额及百分比仍可能被错误标注。不能宣称新增可选工具就已消除此类错误。
2. 报告接口对“人民币百万元”“人民币/股”“百分点”等合理写法拒绝接收，导致反复修补；金融与通用组均受影响。金融组少踩接口错误，不等于金融判断显著更好。
3. 公共Markdown报告附加表格在每行之间插入空行，破坏标准表格结构；部分占位符模板又重复添加百分号。独立生成的正文、CSV与图形仍可能表达不一致。
4. 自由绘图中的色标布局、标题重叠和深色文字对比度问题仍在；既有辅助函数没有被稳定采用，不能用合成图通过代替实际图形验收。

本次仅记录这些缺陷，没有在正式试验中追加修补、金融纠错提示或选择性重跑。安全授权、Pi循环和完整入库能力保持原设计。

## 可复核范围与结论

资料准备一次完成候选覆盖：财报78/78表、732条事实；研报95/95表、47/47页、2222条数值观测及63条观点等记录。16次准备尝试已知输入24,151,907、输出128,715 token，195次早期失败/未知用量请求单列；包含人工续接和准备期修复，不构成无人干预的入库成绩。候选覆盖不代表全篇语义零错，待核验及来源内冲突保留。

正式分析代码摘要为 `ae68084aa44051da5040afd5638b7e035abc657aa576d29696a136253e34bf7a`，准备数据摘要为 `387a3b20ff08637f77bbab428b3c7ccdc72fc7588558fffc616baeabcc17c363`，前后均未变化。数学输出指导在冻结前同时应用各组；试验中仅为前端补充原生TeX定界符显示，不改变模型请求、工具和评分数据。

数值、下载与重放由确定性计算复核，解释及图形由开发者人工审阅，未盲评，也没有独立金融专家评分。两份新资料属于同一公司，主比较每题仅两次；上游缓存热度和宿主负载未控制。墙钟用时包含工具等待、B1恢复及穿插的本地复算，不作为严格性能基准。

结论是：本轮观察到金融组累计输入、输出和返工减少，以及部分现金流解释的收益；但未缓存输入并未减少，参数/金额交付和图形错误仍然存在，模型版本复用也没有稳定发生。**尚不能宣称金融组整体质量或实际费用优于同模型、同数据的通用Pi。** 下一轮若要证明优势，应直接改善工具使用与数值交付的一致性，而不能增加无效的模型复核流程或通过筛选试次改善成绩。
